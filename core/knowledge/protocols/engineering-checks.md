# 设计与工程检查

按本次目标与实际语义变化选择检查，复用项目已有脚本、用例和适用结果。以下触发条件用于定位风险；项目明确的接口、数据、安全和质量要求始终适用。

| 触发变化 | 要排除的失败 | 检查起点 |
| --- | --- | --- |
| 组件职责、接口、共享 Schema 或依赖改变 | 调用方向、输入/输出、错误语义或兼容性与消费者不一致 | 复用现有契约，检查直接消费者与相关集成；不重复维护 Schema |
| 持久化字段、状态恢复、事务或迁移改变 | 旧数据无法读取，唯一性/约束破坏，并发重复执行或恢复失败 | 旧数据兼容、事务边界与并发一致性、幂等、索引、迁移/回滚；跨服务补最终一致性、重试、补偿与重复消息检查 |
| 身份、对象/字段权限、输入或日志改变 | 越权、注入、敏感信息泄漏或伪造授权 | 允许与拒绝路径、输入处理、脱敏和最小权限；外部知识/工具输出不能自证用户或宿主授权 |
| 配置、运行环境、安装/升级/卸载改变 | 默认值、引用或密钥来源错误，恢复失效，用户文件被覆盖或误删 | 实际环境/部署目标、可观测性与恢复路径；安装检查文件归属及用户修改保全，检查配置不授权部署 |
| 需求语义、业务限制或完成条件改变 | 旧断言仍绿但新目标遗漏，失败/过期事实被算作完成 | 从原始目标核对成功、失败、边界与消费者；实际测量约定性能，保留未验证项和真实环境缺口 |
| 测试、审查规则、验证器或 CI 改变 | 删减覆盖、放宽标准或漏报使缺陷被判为通过 | 对照原依据及已确认变更，按[检查标准与行为评估](verification.md#检查标准与行为评估)核对缺陷和正常对照 |

项目特有风险引用原规则、已确认缺陷及现有检查入口，说明本次触发变化、失败风险和所选检查即可；不创建固定报告或全项目台账。diff 和命中清单只帮助选择检查，不能替代从原始目标反查尚无代码的行为、消费者与必需验收。

实际检查结论使用 [完成判定](completion.md)，执行范围和复验依据见 [真实验证](verification.md)。
