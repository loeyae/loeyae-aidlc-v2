# 真实验证与复用

## 限定读取、扫描与输出

每次查询先确定问题和返回形态，再展开必要内容。适用项目指令完整读取；业务资料按下表处理，范围内需要查全的内容在进程内完整分析。

| 需要 | 首次返回 | 按疑点展开 |
| --- | --- | --- |
| 已知 CR、故事或验收 ID | 导航对应行、引用与位置 | 链接指向的接续段或决定；沿引用补查 |
| 未知文件或符号 | 在相关组件中用 rg 查文件名/位置 | 方法及必要调用上下文 |
| 长文 | 当前层级标题 | 指定章节或完整语义段 |
| 改动 | Git 状态、相关路径 diff 统计 | 相关变更块 |
| JSON、日志、SQL 大行 | 解析后的键/类型或相关字段 | 失败、跳过、断言与差异 |
| 用例 | 全部相关候选的 ID、位置、标题、来源引用 | 具体前置、步骤或断言 |

已知文档优先使用随技能分发的[只读查询工具](../../tools/aidlc-query.mjs)：以 node 调用工具路径，参数为 locate <导航文件> <ID>、section <文件> [精确标题或行号]、json <文件> [字段路径...]、references <故事文件> <STORY/AC-ID...> 或 cases <用例文件> <STORY/AC-ID...>。section 默认列顶层目录，选中父节返回开头与子节位置；json 默认给结构，长字符串返回长度和省略标记。可用等价原生查询。

按完整记录边界展开，一次回答一个具体问题；批量查询分别返回定位或投影结果。命中过宽时细化符号、ID、章节或字段；已知文件也不默认全文输出。单行可能包含整份正文，行数/输出预算不能替代解析后投影；前 N 条仅供预览，不能代表全集。保全和比较在本地完成，不以编码、转义或分段搬运全文。已读且未变的片段复用，截断内容仍须按需补查。

从明确入口、清单、锁文件或消费者定位产物与依赖。范围未指向时不展开 node_modules、缓存、构建物、Git 内部或历史报告；发现具体缺陷再扩到相关子树。入口/依赖缺失先核对已知根、配置与解析路径，仍缺失则报告环境缺口，不自动安装或遍历兜底。保护修改只需核对本次路径，不默认全目录哈希。

用户要求完整交付核验、安全审计或实际风险需要完整性检查时，完整检查明确范围内的缺失、意外文件、内容和依赖，生成物同样计入；不连带扫描无关目录。必要构建、测试与 CI 按正常输入执行，结果投影不缩小验收范围。

## 先短回归，再集中核验

按本次运行目的选择验证：已知缺陷先做定向修复验证；恢复整套门禁且独立失败尚未查清时，在既定范围收集完整失败。已有同基线的完整失败记录可复用，不为重新收集再跑全量。

1. CI 排错先取具体失败摘要和失败提交/输入，核对与本地基线的关系；信息不足及时索取，继续不依赖它的调查。从所选测试、共享夹具、项目脚本确认服务/数据库、初始化数据、环境变量、参数、shell 和直接依赖等前置条件。复用适用环境，缺项先轻量定位并在授权内补齐；范围限于所选入口，不新增统一预检门禁。
2. 定向验证运行能区分正确行为与具体缺陷的最短回归。偶发问题优先用可控条件验证原症状与修复；未稳定复现时保留不确定性，单次通过不能证明已经复现或消除故障。规则变化观察首次实际工具调用、加载时点、字段投影或写回结果，不以匹配规则文案代替行为验证。新测试先验证自身夹具和断言；状态/异步变化尽早检查相关形成、恢复、替换、解除及迟到响应。
3. 定向修复验证出现决定性失败时，保留命令、输入、退出码和关键输出，停止尚未开始且依赖该检查通过的昂贵工作，返修后短回归。完整失败收集保持被测输入稳定，让范围内仍有效的独立检查执行完并汇总失败，不因首个用例失败中止后再从头重跑。环境或共享前置失效、继续执行有破坏性风险时，停止或处置受影响运行；其他明确要求的完整检查和仍有效的独立诊断继续，失败及未运行项保留为缺口。用户要求停止时遵从。只取消本次拥有且可安全停止的进程，未知外部操作先核实结果。
4. 沿共同原因查全同类缺陷及直接消费者，包括同类夹具、共享输入和旧断言；不以首次报错文件代替影响范围，也不默认全仓扫描。前置失败可能遮蔽后续断言，修复后先定向补验。按新增差异重选复验：仅改局部夹具或启动参数先跑对应测试，改共享输入扩到消费者。相同失败且没有新信息时缩小复现或改变诊断，不原样循环。已定位问题及受影响短回归收敛后，集中补齐必要全量、类型检查、构建、集成和约定检查。追加全量前判断新失败、相关输入变化或覆盖缺口是否需要全量，或是否为项目明确要求；不因每修一处就从头重跑。
5. 提前核对提交 hook、构建 pre/post 和 CI 的实际覆盖，减少同范围手动重复；项目要求的独立检查与 hook 保留并实际运行。hook 改码、打包后输入变化时补受影响验证，不能直接沿用通过结果。
6. 格式及生成资源整理尽量在集中核验前完成；通过后只处理本次必要修改。分别判断行为、字节校验和与构建产物证据是否失效：纯格式可能要求更新校验和，不自动要求重跑业务链；语义或生成输入变化则补对应检查。
7. 复用前核对相关代码、测试、依赖、配置、业务语义、验收、验证工具及环境/有效期；失败、过期、未运行或依据缺失均不能复用为通过。引用原报告，不为刷新全绿汇总重跑；验证器缺陷在原工具中修复，输入参数化，保留原始失败。

跨会话/宿主行为变化：先短回归，候选稳定后做一次覆盖当前范围的完整新会话验证。提供现行规则、真实任务和原始资料，不提供前轮推理或预期答案，也不在被测任务内递归委派同种验证。复用适用准备成果；仅在新失败、相关输入变化、覆盖缺口或项目要求下追加检查。会话内两个进程不能证明独立模型接手。

以上用于选择验证工作，不增加阶段、许可、固定全量轮次或统一计时中止。优化从原日志观察包含失败试验在内的读取、调用、重复工作与总耗时；单条输出变小不能独自证明整体改善。约定范围满足后按[完成判定](completion.md)交付，建议不自动授权新一轮优化。

## 按实际影响验证

| 实际变化 | 检查起点与扩展依据 |
| --- | --- |
| 文案、样式、布局 | 约定状态/尺寸、可访问性、交互及视觉标准；共享组件变化扩到消费者 |
| 校验、业务逻辑 | 成功、失败、边界、错误路径；按影响检查权限、并发、一致性与提交链路 |
| 接口、数据、依赖 | 契约、消费者、配置、权限、迁移/回滚；补相关集成、安全或性能检查 |
| 业务文档/生成源 | 完整语义、引用、生成物及消费者；决定代码或验收时补行为检查 |
| 不改变语义、生成输入或验收的交付说明 | 必要结构与链接；不因此重跑业务检查 |

UI 仍需真实浏览器、API 与结果导航验证；Mock 不替代真实环境，约定像素标准保留。检查受影响的敏感信息、输入处理、权限与数据完整性；约定性能目标实际测量，缺环境时明确待办。

保留命令、输入/环境、退出码、关键输出、适用范围和未验证项；审查可依据现有代码与结果独立开始。业务口径改变后，从新要求独立检查实际行为，原断言全绿可能仍在验证旧口径；文档语义不能按扩展名豁免。多人汇合或切换基线时核对实际候选与证据输入，各分支通过不能代替组合变化的集成验证。与检查无关的提交号、路径、时间戳或说明变化不自动使行为证据失效。

## 沿既有验收引用查全影响

1. 从已核实基线上的真实未完成行为或语义变化定位原需求、STORY/AC。复用适用分析，检查触发来源、前置、异常与消费者；原目标中尚无代码的内容仍保留，模块归属和旧清单都不是影响边界。
2. 按这些 ID 在已有测试/用例中收集全部引用后判断影响。发现消费者或前置的新 AC 时继续查其全部引用，覆盖造数、清除/回滚、结果断言、异常、边界与并发。缺失/错写 ID 时沿行为和依赖补查，不以手选编号或前 N 条代表全集。
3. 用实际 BEGIN/END、表格记录或元数据边界区分完整用例，避免把下一例的引用归给上一例；共现不等于依赖。同一 AC 的候选不一定都需修改或重跑，排除须有具体无影响依据；保留未确认标注，检索命中不等于批准。
4. 将遗漏的具体 ID、位置、原因与待迁移行为补回获准修改的原权威记录，再核对“已定位 − 已记录”的差集；记录的区间和组合编号必须覆盖具体项。复用已解析集合，笼统的“补验相关 AC”不能代替承接。无权写记录时在对话交付，无权改测试时在原接续段保留待办。
5. 查清关联并说明处置、未验证项及实际缺口；查全、编号出现和写回均不证明实现或验收完成。只读查询工具的 reconcile <记录文件> <精确标题或行号> 从标准输入接收实际 cases JSON/JSONL，也可调用其 query/reconcile 导出。使用原查询结果，不手填或删除候选掩盖差集；空候选、空差集不能证明完整、通过或授权。

候选与差集用于落实本次影响，不另建映射表或门禁，不把每个命中升级为必改/必跑项。框架优化结束不关闭仍未满足的业务目标、必需检查或外部验收。
