# 真实验证与复用

先从用户验收、项目脚本、CI 和实际依赖确定必要检查。不能通过缩小范围、跳过项目必需检查或把失败改成不适用来宣称完成；也不能因为历史阶段清单很长而重复执行没有新增信息的检查。

## 限定读取、扫描与输出

每次查询先选要回答的问题及返回形态，再取内容；第一条资料查询就如此，不等读取详细协议后才收窄。已知文件也不默认全文输出。以下是原生工具的默认用法，不增加工具调用前的记录或审批；适用的项目指令须完整掌握。

| 当前需要 | 先返回什么 | 再展开什么 |
| --- | --- | --- |
| 已知 CR、故事或验收 ID | `rg -n -F '<ID>' <导航或来源文件>` 定位对应行/引用 | 按锚点或标题边界取完整相关段；没有接续段才定位决定与未完成项，不整份输出 handoff、CR 或 progress |
| 未知实现文件或符号 | `rg -l -F '<符号或行为词>' <相关目录>`，或 `rg --files` 按文件名发现 | 选中文件中的方法和必要上下文；不要直接对目录用通用词输出全部匹配行 |
| 长文结构 | `rg -n '^# ' <文件>` 列章级目录；故事汇总先列史诗章 | 指定章下的下一层或精确 ID；不一次查询所有标题层级，更不混入通用正文词 |
| 实际改动与已有脏改动 | Git 状态、限定路径的 diff 统计 | 当前问题相关的变更块；完整差异可在进程内分析，输出问题与定位 |
| 测试 JSON/日志 | 在进程内解析后返回总结果、相关套件、失败/跳过及输入适用性；结构未知先给键名/类型 | 有疑点的具体结果或原始片段；不打印原对象，也不把全部对象序列化后截断 |
| 宽表与用例文件 | 全部相关引用的去重 ID、行号、标题及来源引用，先不带前置/步骤/预期正文 | 有疑点时按 ID 取相关前置/断言，必要时读完整用例；不能将“少输出”变成“只选几个编号” |

内容展开一次只回答一个具体问题，按完整语义段/用例边界读取，不把多份正文或大片段拼成同次输出；批量查询先分别返回定位结果。查状态只匹配精确字段/当前 ID，长文目录只查当前层级，不将所有标题、通用词和业务 ID 合成 `|` 正文查询；长表的一行也可能很大，应先投影字段。例如用例匹配后先 `map(({id,line,title,source}) => ({id,line,title,source}))`，不要同时带上全部候选的前置、步骤和预期；再围绕具体语义疑点展开这些字段。范围限定在正确文件也不等于需要全文输出。

命中过多时改用更具体的符号、ID、章节或返回形态，不提高预算放行宽泛查询。前 N 条只能预览，不能据此判定范围；需要查全时在命令或解析端处理全部相关匹配，返回关联集合或差异，而非直接截断。同一段已读且输入未变时复用，只补读尚未核对的来源或疑点；不先全文后再按标题重读。长结果沿用原报告/工具输出，不另建证据副本。

Git 只帮助定位输入和保护改动，目标仍从原始约定反查，包括尚无代码的目标。保护他人文件默认核对本次写入范围和既有改动；没有 Git 时也先限定要修改的文件，不为证明“其他文件未变”递归遍历、逐文件哈希或建立全工作区指纹。只输出一个总哈希仍属于全目录核验。保全当前未提交正文或比较修改前后时，在本地进程中保留并比较；必要临时文件沿用项目规则并清理，不新增永久副本。不得把文件编码为 Base64、转义 JSON 或分段全文送入聊天再还原；编码不改变它仍是全文输出的事实。

产出物、依赖包与缓存默认从明确入口、清单、锁文件、生成源或消费路径定位，不递归展开整个目录，也不逐包读取正文。检查依赖是否可运行时先查项目脚本和已知包入口/解析结果；入口缺失只核对明确的项目根、清单与解析路径，仍缺失则如实保留环境缺口，不以列举 `node_modules` 顶层名称、搜索整个依赖目录或自动安装作为兜底。范围未指向其中内容时，检索不进入 `node_modules`、包管理器缓存、`dist`、`build`、`target`、`.git`、历史报告和归档目录；不能先全量读取再靠截断减少展示。遇到具体缺陷、依赖关系或所有权疑点再扩到相关子树，不因换会话或存在这些目录扩大。

比较受影响文档的完整语义时，可在本地解析相关文件全部内容，只返回差异和缺失项，不能把计数相同当成语义一致。输出截断时细化查询并补读相关部分，不能把截断、少量样本或没有展示失败当成全部通过。不要输出完整目录清单、逐文件哈希表、整份测试 JSON 或日志。

上述约束不豁免必要检查。用户要求完整交付核验、安全审计，或实际风险要求完整性检查时，检查明确指定的包、产物或依赖范围，包括必需文件缺失、意外文件、内容及哈希；不能只查入口或抽样后宣称完整。范围内的生成物与依赖不能因目录名被排除，但无需连带扫描旁边的其他包、版本或产出目录。必要构建、测试和 CI 仍按其正常输入执行；结果按上述方式披露，不增设扫描审批或台账。

## 先短回归，再集中核验

从本次改变的可观察行为选最短的有效回归，优先复用现有测试命令、固定输入和查询/比较工具。短回归须能区分正确行为与已知缺陷，不能只搜规则文案或证明命令能启动。例如检查首次资料查询、报告字段投影或已定位用例的写回，不先重做整个 CR 审计。规则加载顺序有问题时检查首次实际调用及规则何时可见，不反复修改尚未加载的正文。

得到足以判定本次局部目标失败的结果后，保留原始命令、输入、退出码及关键输出，及时结束这个试验尚未开展的昂贵后续；失败及未运行项仍按事实保留，不能改成不适用或通过。用户/项目明确要求收集完整结果的检查及必要独立诊断仍须执行，不能因找到一个失败就宣称完整检查已结束。需要终止正在运行的试验时，只取消本次创建、所有权明确且可安全停止的任务/进程；不按进程名批量终止，不接管未知进程，不把外部操作响应未知当作未执行。修复问题并重跑受影响短回归，其他独立工作继续；停止试验不等于放弃原目标或关闭 CR。

短回归通过后按下一节的实际影响补齐必要检查。相关输入没有变化且结果仍适用的检查直接引用原报告；不要为每个候选重做完整性反例、正文保全或业务审计。复用前核对实际相关代码、测试、依赖、配置、业务语义、验收、验证工具及环境/有效期，不能只凭提交号、文件名或一次通过；关联不明或原结果缺失时补查，确实受影响的部分重新验证。失败、未执行和过期结果不能复用为通过，当前 CI 和约定的必需检查仍满足其原要求。沿用原记录，不新建证据台账、输入指纹库或签名回执。

验证工具自身出错时区分工具缺陷与产品失败，在原测试结构中修正可复用实现；不要每轮复制准备、执行、快照和比较脚本，或按自由文本格式重写结果解析器。输入作为现有工具的参数，原始结果保留；工具结果不能自行认证业务覆盖、授权或完成。

需要跨会话/宿主验证时，候选稳定且局部行为已核验后，集中安排一次当前范围的完整新会话核验。从现行项目规则、原目标、实际成果和适用证据接手，不继承前会话推理、不喂预期答案，也不要求重做全部未变工作；核对目标、依赖、写回、完成和权限边界。发给新会话的任务保持本次范围，不把局部规则回归写成全项目审计，不在被测任务内再委派同一种验证。原有准备成果仍适用时复用，无须重跑准备会话。此后只有相关输入变化、新失败或覆盖缺口才补验；广泛变化或项目明确要求时保留必要的完整重验。

以上是选择验证工作的方式，不是新增阶段、许可、默认计时中止或定期全量试点。最终仍逐项反查原目标及全部必需验收，未满足的条件按[完成判定](completion.md)保留。优化效果从已有执行日志观察总耗时、命令/模型调用、输出及重复工作，包含失败试验；不能只看单条输出缩小或把必要验证移出统计范围。

## 按实际影响验证

| 实际变化 | 最小检查起点 | 扩大范围的条件 |
| --- | --- | --- |
| 文案、样式和布局 | 受影响状态/尺寸、可访问性和交互；既定视觉标准 | 共享组件、布局约束、其他消费者变化 |
| 校验、业务逻辑 | 有效、无效、边界与错误路径 | 共享校验器、并发、一致性、权限或提交链路变化 |
| 接口、数据、依赖 | 契约与消费者、权限、迁移/回滚、配置 | 跨服务集成、兼容性、安全或性能风险 |
| 业务文档/生成源 | 语义与引用、对应生成物和消费者 | 文档决定代码、测试或验收行为 |
| 不改变业务语义、生成输入和验收要求的说明或交付记录 | 必要结构与链接 | 一旦改变上述内容，按业务文档/生成源检查 |

功能检查必须覆盖成功、失败和边界；UI 检查包括约定状态、尺寸、可访问性、交互、真实 API 和结果导航，已有像素标准保留。按实际影响检查敏感信息、输入处理、权限与数据完整性；有性能目标时实际测量。无法运行真实环境检查时保留待办，不能以 mock 结果替代。

验证结果保留实际命令、环境/输入、退出码、关键输出、适用范围及未验证项；原始报告可直接引用，不重复抄写数值或制作签名证明。审查依据实际代码和测试；构建、测试与审查可独立开始。

代码、测试、依赖、运行配置、业务定义或验收要求的相关变化会使对应结果失效。业务口径变更后，从新目标独立检查实际行为；原测试可能仍在验证旧规则，不能仅重跑原断言就宣布满足新需求。沿[既有验收引用](#沿既有验收引用查全影响)查明受影响集合，再选择复验范围。与检查无关的交付说明、记录顺序和时间戳变化不使业务结果失效；不能把整个 Markdown 目录排除。

多人成果汇合或切换基线后，核对实际候选与各结果的相关输入。各分支通过不能相加为集成通过；接口、数据约束、共享组件及消费者的组合变化需要实际集成检查。只重验受影响部分，未变结果保留引用；单纯提交号、工作树路径或交付说明变化不自动触发全量重跑。

失败后检验原因、修复并重跑受影响检查。同样输入和错误没有新信息时，缩小复现或变更诊断方法，不原样循环。外部阻塞只挂起对应验收，继续独立实施。所有结论使用 [完成判定](completion.md)。

## 沿既有验收引用查全影响

1. 从本次改变或废止的行为找到现有需求、STORY/AC；检查完整行为，包括触发来源、前置条件、异常和消费者，不能只核对改动点或旧清单列出的故事。
2. 在已有用例/测试位置按这些 ID 收集全部引用，返回去重后的用例 ID、位置与关系，再判断影响；不能先手选编号，再拿选中项代表全集。发现消费者或前置的新 STORY/AC 后，对新 ID 同样查全部引用，包括不同编号区间的异常、边界和并发用例。继续核对造数、前置用例、清除/回滚及结果断言，直到相关引用没有尚未核对的项；旧清单范围和查询前 N 条都不是边界。
3. 按文件实际结构界定完整用例：现有 BEGIN/END 标记、表格记录或元数据边界优先，不能把下一例的 source_ref 归给上一例；仅共现不等于前置依赖。逐项比较候选与新语义，没有 ID、缺失/错写 ID 时沿行为及依赖补查。正常流程、共享造数、失败边界及并发需要一起判断；“主体行为保留”不能掩盖前置改变。同一 AC 不表示每例都需改动或重跑，排除须基于具体无影响关系，不能只选几个代表。原有未确认标注仍保留，不能因检索命中变成已批准要求。
4. 在进程内维护本次相关集合即可；只输出编号/位置、原因、应保留或迁移的行为与未验证项，不整卷打印用例表。将具体遗漏补入现有权威任务/CR 的待办或接续段；完成写入后，重新读取该段并与已定位受影响项比较，检查“已定位 − 已记录”的差集。记录的区间/组合编号须实际覆盖对应项及原因；把差集补回原段，确实无影响的项按语义排除，不能把“已经看过”“补验相关 AC”或笼统“验证并发”当成已承接。输入未变时沿用已解析集合，不为这一步重新扫描项目。
5. 遵守当前写入授权：无权改测试或历史清单时，在获准的现有接续记录说明待迁移项；无权写权威记录则在对话交付，不写导航或新台账代替。未查清的关联和不能运行的验证保留缺口，不能宣称影响已全部核对。查全和写回证明任务得到承接，不证明实现、验收或交付已完成。

可复用随 Skill 分发的 `aidlc-query.mjs`，在同一进程保留查询结果，避免再次手工拼出 `located` 集合或复制比较脚本：

```js
const refs = query(project, ["references", storyFile, ...storyIds]);
const results = caseFiles.map(file => query(project, ["cases", file, ...refs.references]));
// 判断实际影响，按授权更新现有记录；相关输入未变时复用 results。
const difference = reconcile(project, recordFile, recordHeading, results);
```

`query` 与 `reconcile` 均由该工具导出。CLI 也可将实际 `cases` JSON/JSONL 经标准输入交给 `reconcile <记录文件> <精确标题或行号>`。比对限定在该记录段，识别编号区间和同一列表内的简写；未解析引用及编号写法继续返回。结果仅说明编号出现关系：合理排除须有语义依据，编号出现不等于已承接，空候选或空差集不证明查全、通过、授权或完成。不能删除结果中的候选来隐藏差集，也不能把工具返回的未出现项一律升级为必改、必重跑的业务用例。

这是一种按实际语义追踪影响的方法，不要求新编号、映射文件、完成矩阵或独立门禁；原始目标、必需检查与权限仍按现有规则判断。

验证或优化任务满足本次约定范围后，按[完成判定](completion.md)交付收口，保留已知限制；效率建议、环境波动或验证器问题不自动触发下一轮规则改版、发布或完整新会话。后续由真实任务中可复现的具体缺陷触发有界修复，复用适用证据。业务任务尚未满足的目标、必需检查与外部验收仍保持未完成，不能随框架优化任务一同关闭。
