# 完成判定

本规则适用于所有任务、方法、CR 和续作。按当前授权范围、约定验收、实际实现、最新适用验证及未决项得出结论；不得从阶段数、空队列、退出提示或知识加载推断完成。

| 结论 | 必须具备的事实 | 不足时如何报告 |
| --- | --- | --- |
| 实施完成 | 已约定实现及必要业务文档齐备，审查无未解决实现缺陷 | 明确未实现或需返修部分 |
| 本地已验证 | 实施完成；全部必需本地检查实际通过，结果对应当前相关输入 | 失败、未运行、无原始依据或过期均保留缺口 |
| 验收完成 | 本地已验证；全部约定业务/真实环境验收满足，必要决定已落实 | 可报告本地完成、外部验收待办；不能称全部通过 |
| 交付动作完成 | 用户要求且已授权的提交、推送、合并、发布或部署实际完成 | 列出待执行动作；测试不授予执行权限 |
| CR 关闭 | 已约定关闭条件全部满足，决定、验证、遗留项可追溯 | 保留 CR 待办，不为闭合清单编造批准或预先清理记录 |

如用户范围是分析、文档或局部修复，按该范围验收，不自动扩成全项目。明确受影响依赖和范围覆盖后才总结；范围或验收缺失、空清单、部分覆盖只能报告未评估。可承认实施部分完成，但整体未完成。已知验收阻塞项不能隐藏，外部等待不能伪装成本地缺陷。

项目级结论先对照原始约定、已确认变更及现有任务清单，核对所有模块和必要集成、迁移/回滚与交付条件；单元通过不能替代项目覆盖。`coverage: complete` 是宿主核对后的声明，工具不能发现输入中被遗漏的需求。不能用全绿的子集或省略必需交付字段制造完成。

性能独立报告；只有被约定为验收条件时才影响验收。用户指定截止时间时遵守，不设通用时长中止门禁。

可选 `loeyae-aidlc assess --input <已有结果.json>` 对宿主提供的事实生成同一判定视图；它不执行测试、不认证事实、不写状态、不授予权限，也不是交付前置条件。`work` 永远返回未评估。事实须来自真实实现和验证；派生视图不能代替原始证据。

CR 清理在关闭判定和可追溯条件满足后，遵循用户/项目要求进行；未提交、唯一记录和他人文件保留。提交、合并、部署分别判断，不能从其中任一项推断其他项。
