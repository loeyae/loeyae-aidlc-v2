# 项目接手与资料收敛

旧项目、资料冲突或跨会话接手时使用；普通局部修改无需遍历历史或迁移全部文档。已知 CR ID 时先取导航中对应行，再读所指接续段；其他事实沿引用定位。读取、产出物/依赖扫描与输出遵循[真实验证](verification.md#限定读取扫描与输出)，不为接手制作全目录哈希或加载整卷故事、历史和测试日志。沿用现有需求、任务说明和宿主记录，不建立接手台账、版本兼容模式或恢复门禁。

## 恢复当前目标

先从用户原始约定及可核验的已确认变更定位本次目标、验收和授权，再看交接摘要、现有清单与实际代码。摘要只能定位来源，不能取代来源或扩大授权；文件日期较新、勾选完成或写有“已批准”本身不证明其权威。真实授权适用性按[权限边界](permissions.md)核对。

“完整”以本次用户范围及已确认变更为界。局部 CR 先定位变更决定及实际依赖，不把整个模块的需求/NFR 自动列为待重验；交接中的“整体核验”或复制件缺少其他实现，都不是扩大范围的依据。扩展到消费者、端到端链路或非功能检查时说明具体受影响关系；未受影响的既有结果沿用，材料未提供只说明本次证据边界，不写成新增实施缺口。

在这个范围内逐项检查目标行为、必要消费者/集成、数据迁移/回滚和交付条件，包括尚无实现或测试的项。旧测试清单只作定位起点；按[既有 STORY/AC 引用](verification.md#沿既有验收引用查全影响)查全相关用例及前置依赖，把遗漏的具体编号、位置和原因补回现有权威接续段，不能仅重复旧编号区间或“补验相关 AC”。已有测试全绿时仍检查是否沿用旧口径；验收语义改变才使对应结果失效，文档路径或摘要变化不自动触发重跑。外部待办保留边界，不另建目标矩阵。

同一 CR 的“产品文档完成”“代码完成”“验收完成”“关闭”分别判断。一个参与者完成自己的范围不取消其他参与者的待办；摘要省略、旧清单勾选或子集通过不能证明整体覆盖。`work` 的截断预览只能定位资料，相关完整内容需由宿主按需读取；`assess` 不会发现输入遗漏，按[完成判定](completion.md)收口。

## 处理旧流程残留

旧阶段命令、claim/grant、refresh/re-attest、补签名、固定审批轮次及过期状态仅说明历史流程，不恢复旧运行时、不重跑阶段。业务决定、原始失败与验证依据继续保留；项目现行 CI、安全、质量和发布权限要求仍有效，不能因它们出现在旧文档中一并废弃。

遇到“已确认”与“待拍板”并存，先沿来源找到真实答复及适用范围；有效且未被覆盖的答复直接复用。仍有真实业务歧义或无法核实的授权时，只暂停依赖部分；不得根据版本号、推荐选项或 AI 摘要代替用户决定。现行项目指令与当前任务存在真实冲突时处理具体冲突，不把“旧流程”当作绕过项目指令的理由。

当前任务涉及这些入口且有写入权限时，就地把失效的行动提示替换为现有来源和剩余工作引用，清除已解决的“待批准”提示。只更新本次接手会用到的 CR/任务入口；纯历史记录无需改写，唯一、未提交或他人维护的材料保留。安装新版规则不等于项目资料已迁移，也不授权批量清理工作区。

## 收敛重复资料

同一故事、决定或状态已有多份正文时，先看实际维护者、引用及消费者，选定现有权威来源。比较并保留副本中的独有验收、例外和未决项，再将可编辑的重复正文替换成指向原来源的短引用；保留仍被引用的 ID/锚点，核对链接和调用方。无法确认哪份有效时保留冲突并调查，不能以“去重”删除需求。

先沿现有引用识别哪份 CR、任务说明或交接正文维护当前事实，其他入口仅导航；文件名为 handoff 不意味着它也要保存状态。链接有效、权威来源未迁移时，不因新会话、日期、完成状态或测试数变化改写导航，也不在链接标题或表格行加“进行中”“不能关闭”“本轮已核验”等状态摘要。首次缺少入口、断链或来源迁移时才调整必要引用；失效的手工状态副本在授权范围内一次收敛，后续不再同步。既有生成视图或用户明确要求的状态展示从权威来源派生，不新增手工维护点。

先区分手工副本与生成物：生成物维护其源和生成方式，独有修改先回归源；生成器缺失不证明生成物失效。未确认消费者与交付形态可变时，保留生成物的完整正文，不能直接改为索引或要求下游适应删减。独立消费者必需的契约、可执行测试及约定交付物保留。无权修改的副本通过当前入口指明来源，不能接管他人文件。仅当本次变更触及重复内容时收敛，不为文档整洁扩大任务。

## 继续未完成工作

核对当前仓库、分支、未提交成果及验证适用输入；按现有分工处理共享接口和实际写入重叠。先查询宿主可见的未决操作：超时不等于未执行，提交、推送、发布、迁移等不能盲目重放；结果未知只挂起相关操作，独立工作继续。不接管未知进程，不因交接创建强制 worktree 或全项目锁。

需要持久续作时只在上述既有权威记录中补充新的事实、未完成目标、适用验证和下一步引用；新会话本身不是文档更新理由。没有新事实时保留记录，在对话中说明结果；无权写入权威记录时先完成独立工作并说明待归源内容，不把导航或新文件变成第二份记录。接手者独立核对原始目标与实际输入；只重验受影响部分，不重建全量基线。

同一会话或两个 CLI 查询进程不证明新模型会话恢复。跨会话/换宿主验证需让独立模型从实际资料接手，核对真实动作和产物，并明确未测的自动唤醒、外部操作恢复等边界。
