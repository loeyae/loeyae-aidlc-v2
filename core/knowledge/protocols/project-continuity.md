# 项目接手与资料收敛

用于旧项目、资料冲突或跨会话续作。已知 CR 时先取导航对应行，再读所指接续段；其他事实沿引用展开，复用已读且未变内容。按[限定读取](verification.md#限定读取扫描与输出)定位资料，不因接手遍历历史、整卷故事或全部依赖。

## 恢复当前目标

从用户原始约定及可核验的已确认变更恢复目标、验收和授权，再对照摘要、清单与代码。摘要、文件日期和“已批准”文字只提供线索；授权来源与当前操作者/操作/环境的适用性按[授权规则](permissions.md)核对。

## 核实实际代码基线

修改或安排回归前，核实相关仓库的 HEAD、工作区改动、远端及真实工作分支；多仓库分别判断，本地 main/tracking branch 不保证是最新实施分支。

1. 从接续、分工或相关提交定位候选分支。没有仍适用的远端核对结果时，获取相关远端引用；已有对象与远端 SHA 一致即可复用，需要对象时再 fetch，不自动 pull 或全仓库同步。
2. 沿任务 ID、修复提交及相关代码确认行为是否已修、当前分支是否包含修复和原证据是否适用；提交标题、存在远端提交均不能独自证明正确、合并或部署。核实后直接处理剩余工作。
3. 保护未提交成果与他人改动。发现基线过旧时停止重复实现，保全补丁，按真实差异重新判断实现和证据；读取远端不授权覆盖、stash 他人成果或合并。必要隔离使用宿主已有能力，不强制新 worktree。

无远端、无法访问或分支关联不明时保留缺口，仅限制依赖它的修改或完成声明；独立工作继续。输入未变的核对结果沿用。

## 围绕真实未完成项收窄工作

对照原目标、已核实实现和适用证据，区分未实现、缺验证、待外部验收与待交付动作。已完成部分复用；局部 CR 的范围按实际行为和依赖扩展，不能从“同模块”或交接中的“整体核验”自动推出全量审计。材料未提供只表明证据边界，不等于缺少实现。

按原目标保留必要消费者/集成、迁移/回滚及交付条件，包括尚无代码的项。未决语义与覆盖缺口沿[STORY/AC](verification.md#沿既有验收引用查全影响)查全，并将具体遗漏归回原记录、核对差集；已有测试全绿仍需排除旧口径。当前没有可独立推进项时报告实际待办，不用无关整理填补外部等待。

实施、验证、交付与关闭按[完成判定](completion.md)分别判断；个人或子集完成不取消其他待办。work 的预览仅用于定位，assess 不会发现输入遗漏。

## 提交与推送续作

用户仅要求提交/推送时，复用现行规则和适用证据，核对工作区/暂存差异、具体授权、目标分支及必要远端增量，明确暂存本次路径。仅新增改动、远端整合或证据缺口触发[补验](verification.md#先短回归再集中核验)。保留并实际运行原 hook，自动改码后按影响补验；推送以实际结果和远端 SHA 核对，多仓库独立交付。

Git 失败先区分权限、认证、网络、引用和对象问题，超时/502/pack 数量不是损坏证据。确有坏对象或索引不一致时，先核对可读成果、受影响引用及 hook 的仓库定位方式，再选择有依据的恢复路径，停止同条件重试。必要且获授权时使用能完整运行原 hook 的干净检出；核对远端基线、原暂存内容和 hook 后差异，不通过替换元数据盲试或绕过 hook。

不默认 repack、删对象、强推或覆盖工作区。权限缺失、唯一成果不可读、写入冲突或外部操作结果未知时，仅挂起对应动作；先查实际结果再决定重试。

## 处理旧流程残留

旧阶段、claim/grant、补签名和过期状态只说明历史流程；业务决定、原始证据及现行项目 CI、安全、质量与发布约束仍有效。发生真实指令冲突时处理具体冲突，不用“旧流程”绕过要求。

“已确认”与“待拍板”并存时，沿来源核对真实答复及适用性，将未实施/未验证和未决定分开。有效决定直接复用，推荐选项或 AI 摘要不代替用户答复。只在本次会使用且获准修改的入口纠正失效行动提示，指向现有来源与剩余工作；保留纯历史、唯一、未提交及他人材料。

纠正仍决定当前实施、消费、验收或约定交付的过时语义；无关历史不逐份改写。安装新版规则不表示资料已迁移，也不授权批量清理。

## 收敛重复资料

沿维护者、引用、生成关系和消费者选择现有权威来源。比较并保留副本中的独有验收、例外、未决项及仍被引用的 ID/锚点，再把获准修改的重复正文改为稳定引用；来源不明时保留冲突并调查。

导航只定位来源。链接有效且来源未迁移时，不因新会话、日期、状态或测试数更新导航；首次缺入口、断链或来源迁移时才调整。既有生成视图和约定状态展示从权威来源派生，避免新增手工同步点。

生成物维护其源与生成方式，独有修改先归源；生成器缺失不证明生成物可删除。消费者和交付形态未确认可变时，保留完整正文、必要契约和可执行测试。无权修改的副本只指出来源；仅收敛本次触及的重复内容，不扩展成全项目整理。

## 继续未完成工作

复用已核实基线与适用结果，按现有分工处理写入重叠和共享契约。恢复的是原目标、授权及剩余验收，不能把摘要中的“下一步”当作全部任务。优先使用宿主原生会话恢复、任务查询、等待和进程句柄；先查询已有任务是否仍在执行，避免另起重复任务。没有原生恢复能力时，从实际代码、原始约定及证据接手，不为 AIDLC 增设调度器、守护进程、运行锁或状态机。

确需持久续作时，在原权威记录补充新事实、剩余目标、验证引用和下一步。未决操作只保留恢复所需的原生任务/会话标识、目标环境、输入或产物版本、结果查询方式及已有幂等键，引用宿主日志；不复制完整日志，不新增 AIDLC 操作台账，不写入凭据。无新事实则保留记录，在对话说明。无权写回时交付待归源内容，导航不成为第二份状态记录。

恢复后沿原目标继续实施、验证、返修和[验收](completion.md)，已有授权仍按原范围适用，不增加阶段审批。独立接手者核对原目标和实际输入，仅补受影响验证。跨会话/宿主验证按[验证顺序](verification.md#先短回归再集中核验)进行，说明实际测试的宿主、原生恢复方式及未测边界；两个 CLI 进程本身不证明模型恢复，自动唤醒能力也不能从会话恢复推断。

## 外部操作结果恢复

对已授权的发布、迁移或外部写入，在发出请求时就保留可恢复的查询线索：目标环境、输入/产物版本，以及服务实际支持的请求标识、幂等键或唯一业务关联字段。优先沿用宿主操作日志；确需持久记录时写回原任务，不建立另一份台账。只能在响应中取得任务 ID 时，先明确响应丢失后如何按原请求或目标查询，不能把“稍后会返回 ID”当作可恢复依据。

超时、断线、进程退出或返回体丢失均不能证明操作未生效。提交、推送、发布、迁移、外部写入等结果未知时，先使用原操作标识查询服务端权威结果，并核对目标、输入版本与产物。声明文件、聊天摘要、客户端退出码或日志中的“已提交请求”不代替实际结果。

| 查询到的事实 | 宿主下一步 |
| --- | --- |
| 仍在执行 | 等待或查询已有任务，复用原生句柄；不另发同一操作。 |
| 已成功且结果匹配本次目标 | 验证实际产物及约定后置条件，复用该结果并继续剩余验收。 |
| 权威端明确未执行或已失败 | 核实是否有部分副作用、授权是否仍适用以及重试是否安全；满足条件后按服务语义复用原幂等键重试，不把失败自动等同于可重放。 |
| 仍未知、查不到或查询不可用 | 缩小到该操作待确认，保留查询线索并继续独立工作；没有证明时不重复写入、不自动回滚、不宣称外部验收完成。 |

“查不到”只有在服务明确保证查询完备且排除延迟、权限和错误目标时，才可作为未执行证据。成功状态属于其他请求、目标或旧输入版本时，仍不能确认本次结果；核对原操作及资源的实际后置条件。幂等键只使用服务真实支持的机制，不能自行发明键后声称重复安全。恢复动作同样受原权限边界约束；不得终止归属不明的进程、重新部署或扩大环境权限来试探结果。真实授权不足时仅等待对应决定，已授权且可独立完成的工作继续。
