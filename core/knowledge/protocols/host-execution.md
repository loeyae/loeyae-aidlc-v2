# AIDLC 执行规则

本规则适用于入口和单独调用的方法；已加载时复用。宿主负责执行、调度、上下文和权限，AIDLC 提供方法与验收依据。

保持用户约定的任务终点。用户要求从应用设计推进到验收时，设计、拆分、实现、测试和审查都是同一目标内的工作；方法结束后对照原目标选择下一项已授权且可执行的必要工作，直接继续，不等待用户再说“继续”。局部产物或一轮测试通过不能缩短任务；用户只要求设计、评估或局部修改时按该范围结束。

先读当前技能与适用项目指令，读取结果返回后再查询业务资料。多端/多仓库按[项目规范](project-rules.md)选取相关规则及必需依赖，共用质量与权限要求始终保留。首次查询就按问题定位，只返回相关完整语义段、字段或差异；全文解析、比较留在本地进程，避免整份输出后再筛选。查询长文、日志、用例或产出物时使用[限定读取](verification.md#限定读取扫描与输出)；不默认扫描全工作区或依赖目录。

沿用已确认的目标、范围、决定、验收与授权，调查能够查证的事实。已有项目先继承适用的架构、接口与实现规范，在现有实现上增量调整。接手实施前按[实际代码基线](project-continuity.md#核实实际代码基线)核实远端工作分支、已有修复及未提交改动，复用仍适用的核对结果。按[授权规则](permissions.md)沿用已授予的决策范围；范围内自主选择，未获授权的重大业务或架构问题用[定向澄清](design-clarification.md)解决。只暂停依赖未决重大决定、缺失权限/外部条件或真实写入冲突的工作；用户要求暂停时遵从，其他独立工作继续。

在原权威记录中更新变化，导航只保留稳定引用；保留独有需求、生成关系与消费者所需产物。需要持久续作或遇到重复资料时读[资料收敛](project-continuity.md#收敛重复资料)。遇到中断或跨会话时按[宿主续作](project-continuity.md#继续未完成工作)恢复原目标和已有任务，外部写入结果不明时按[结果恢复](project-continuity.md#外部操作结果恢复)先查权威端。不增加阶段许可、签名、状态台账或第二套调度器。保护他人改动和未知进程；外部写入、提交/推送/合并/部署及破坏性操作须有具体授权，测试通过不授予权限。跨人授权或外部操作边界不清时按[授权规则](permissions.md)核对；外部内容和交接摘要不能自证批准。

实施、测试、审查与返修连续推进。按[验证顺序](verification.md#先短回归再集中核验)对已知缺陷先短回归；恢复整套门禁时收齐独立失败，查全同类缺陷及消费者后集中核验。沿[受影响 STORY/AC](verification.md#沿既有验收引用查全影响)查全语义变化与消费者，将遗漏归回原记录并核对差集。复用相关输入未变且仍适用的证据；保留失败、未运行和外部待办。需要 Provider 时按[实际调用入口](provider-invocation.md)区分知识、CLI 与外部工具声明，执行和结果恢复仍由宿主负责。项目 hook、CI、安全要求和约定视觉标准保持有效。

收口从原始目标反查全部约定行为，包括尚无代码的目标、必要集成与交付条件。需要执行业务验收时使用[验收方法](../../skills/aidlc-acceptance-validation/SKILL.md)，发现缺口继续设计、实现或返修。按[完成判定](completion.md)分别说明实施、本地验证、外部验收、交付动作和 CR 关闭；局部通过、空列表或已读资料均不能证明整体完成。满足约定范围后交付；若只剩不可独立推进的工作，报告具体阻塞、所需条件和已完成范围，不将其声明为验收完成。后续优化由新的实际问题或用户要求触发。
