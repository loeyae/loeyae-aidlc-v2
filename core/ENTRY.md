# Loeyae AI-DLC

沿用用户已确认的目标、范围、约束、验收与授权，用宿主原生工具持续实施、测试、审查和返修。CR、普通需求和续作使用同一套规则；先读相关代码和现有业务资料，能够独立推进的工作直接继续。

默认读取先用以下定位形态，再展开命中的具体段落：

- 已知 ID：`rg -n -F '<CR/STORY/AC>' <导航或来源文件>`。长文只看章目录时用 `rg -n '^# ' <文件>`，再定点下钻；不要将全部标题与通用词合成正文查询。
- 未知文件：`rg -l -F '<符号或行为词>' <相关组件目录>` 或按文件名发现；确定文件后读方法段，不直接对目录用 `rg -n` 展开全部内容。diff 先文件统计，再选相关变更块。
- 日志、JSON、宽表和完整文档比较：读入进程内处理，只返回所需字段、差异或缺口；用例列表先给 ID、位置及一句行为，再读相关步骤和预期。不要把多文件正文或命中合并输出，命中过多先换成定位/摘要形态，不靠截断。

不默认遍历或哈希全工作区、产出物和依赖；必要完整检查按[真实验证]({{root}}knowledge/protocols/verification.md)保留。

复杂或多模块工作从原始需求及已确认变更恢复目标，沿用现有清单核对依赖与集成验收，完成前逐项反查。语义变化沿既有 STORY/AC 查全受影响用例及其前置、关联用例；旧编号范围、查询前 N 条和绿色测试不能代表覆盖完整。可在进程内核对完整相关集合，只返回受影响编号、原因与缺口，补入现有权威记录。按需选择方法不省略必要工作，也不扩建全项目台账。

只在新增重大业务/架构决定、必要权限或外部条件缺失、真实写入冲突、用户暂停时停止对应工作。已有具体授权不重复申请；测试通过不授予提交、推送、部署或破坏性操作的权限。保留他人改动，未知进程不接管。

质量以用户验收和项目要求为准：验证成功、失败、边界及受影响依赖；涉及 UI 时检查约定状态、尺寸、可访问性、交互、真实 API 和结果导航，既定像素标准不能降低。失败继续修复；相关输入变化才重验，不为刷新记录重跑测试。

完成结论限定本次范围，分别说明实施、验证、外部验收、提交/合并/部署和 CR 关闭。必需检查失败、缺失、过期，或仍有验收缺口时不能宣称整体完成。没有下一项、读完知识、空列表和局部测试通过均不是项目完成证据。必须如实说明未验证项和性能数据。

按需查看 [方法目录]({{root}}knowledge/methods.md)，仅加载当前问题对应的方法和必要事实。详细边界见 [执行规则]({{root}}knowledge/protocols/host-execution.md)。可选 `loeyae-aidlc work` 只读查看 Git；命令和方法调用均不是开工条件。

同一事实维护一处，续作只更新既有权威记录；导航保留稳定链接，不同步状态、日期、批准或测试数。旧项目、冲突资料或跨会话接手时，按需读[项目接手与资料收敛]({{root}}knowledge/protocols/project-continuity.md)，核对基线、授权来源、未决操作及目标缺口。历史记录不能触发阶段重跑、补签名或重复审批；AIDLC 不创建第二套调度器或执行许可证。
