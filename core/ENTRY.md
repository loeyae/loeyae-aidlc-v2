# Loeyae AI-DLC

沿用用户已确认的目标、范围、约束、验收与授权，用宿主原生工具持续实施、测试、审查和返修。CR、普通需求和续作使用同一套规则；从当前问题定位相关代码和权威资料，能够独立推进的工作直接继续。

先加载本入口与适用项目指令，读取结果返回后再选择业务查询；不要把技能加载和 handoff、CR、故事或报告正文读取合并成同一调用，否则规则尚未读到就已输出全文。上下文中已完整载入的指令直接复用；其余按适用文件或完整小节读取，不拼接多份规则全文后再重读。无需为此建立记录、回执或审批。

首次资料查询就按问题选择以下返回内容；已知文件路径不等于需要全文。不要先打印整份文档或 JSON，再回头定位、筛选；适用的项目指令仍须完整掌握。

已知文档/报告时优先使用随 Skill 分发的[只读查询工具]({{root}}tools/aidlc-query.mjs)，把 `<工具>` 换成该文件的实际路径：

```text
node <工具> locate <导航文件> <CR-ID>
node <工具> section <所指CR文件>
node <工具> section <所指CR文件> <精确标题或行号>
node <工具> json <报告文件> <字段路径> ...
node <工具> references <故事文件> <STORY/AC-ID> ...
node <工具> cases <用例文件> <STORY/AC-ID> ...
node <工具> reconcile <权威记录> <精确标题或行号>
```

`section` 默认返回顶层目录，选中父节只返回开头与子节定位；`json` 无字段时返回结构，字段支持 `testResults.*.status`，不会展开对象全文。`references` 展开指定 STORY/AC 的全部子标题引用，`cases` 查文字引用候选；`reconcile` 从标准输入接收实际 `cases` JSON/JSONL，核对指定记录段的编号差集，避免手填候选集合。它们不判断实际影响、排除依据或完成；无候选、无差集都不是通过。可用等价原生查询，不要求安装命令或回执，权限与完成判定不由此工具产生。

- 接手已知 CR：先用 `rg -n -F '<CR-ID>' <导航文件>` 取对应行，再按链接锚点/标题边界读该 CR 的接续段；没有接续段才定位决定与未完成项。不要整份输出 handoff、CR 或 progress；其他事实沿引用展开，同一段已读且未变就复用。
- 未知文件：`rg -l -F '<符号或行为词>' <相关组件目录>` 或按文件名发现，再读选中文件的方法段。长文结构用 `rg -n '^# ' <文件>` 查顶层，再查选中章的下一层；查状态只用精确字段/当前 ID，不把所有标题、STORY、模块词等合成 `|` 正文查询。依赖先查已知包入口；diff 先统计，再读相关块。
- 测试 JSON/日志：先在进程内识别结构，再返回总结果、相关套件、失败/跳过和证据适用范围；结构未知时只返回键名、类型，不输出原对象。完整文档比较也在进程内完成，只返回差异/缺口；不能靠截断压缩全文。

内容展开一次只回答一个具体问题，不把多个文件的大片段拼进同次输出。用例候选列表只投影 `id、位置、标题、来源引用`；需要判断影响时再取相关前置/断言，不将全部候选的步骤和预期一起展开。原文保全/比较用已有 Git 基线或本地进程完成，不输出 Base64、转义 JSON 等编码全文来搬运文件。需要读全的源留在本地计算，不能把“范围已限定”当作全文输出的理由。

不默认遍历或哈希全工作区、产出物和依赖；必要完整检查按[真实验证]({{root}}knowledge/protocols/verification.md)保留。

复杂或多模块工作从原始需求及已确认变更恢复目标，沿用现有清单核对依赖与集成验收，完成前逐项反查。语义变化按[既有 STORY/AC 引用]({{root}}knowledge/protocols/verification.md#沿既有验收引用查全影响)收集完整候选集合，再逐项判断影响；发现消费者的新 AC 后查其全部引用，不能先手选熟悉的用例编号。前置、异常、边界和并发也须核对。只返回编号、位置、关系与缺口；写回现有权威记录后，在进程内比较“已定位受影响项 − 已记录项”，把剩余项补回或说明真实排除依据。已读不等于已记录，记录也不等于验证通过。不另建集合台账或完成门禁。

只在新增重大业务/架构决定、必要权限或外部条件缺失、真实写入冲突、用户暂停时停止对应工作。已有具体授权不重复申请；测试通过不授予提交、推送、部署或破坏性操作的权限。保留他人改动，未知进程不接管。

质量以用户验收和项目要求为准：验证成功、失败、边界及受影响依赖；涉及 UI 时检查约定状态、尺寸、可访问性、交互、真实 API 和结果导航，既定像素标准不能降低。局部改变先短回归；已有决定性失败时结束对应试验的后续昂贵工作，修复后复验受影响项，独立工作继续。按[验证顺序与复用]({{root}}knowledge/protocols/verification.md#先短回归再集中核验)复用仍适用的证据和工具，候选稳定后集中做必要的完整核验；局部通过不替代必需检查，不为刷新记录重跑。

完成结论限定本次范围，分别说明实施、验证、外部验收、提交/合并/部署和 CR 关闭。必需检查失败、缺失、过期，或仍有验收缺口时不能宣称整体完成。没有下一项、读完知识、空列表和局部测试通过均不是项目完成证据。必须如实说明未验证项和性能数据。当前授权范围满足后交付收口；一般改进建议不自动授权下一轮优化，后续由真实任务中可复现的具体缺陷触发有界修复。

按需查看 [方法目录]({{root}}knowledge/methods.md)，仅加载当前问题对应的方法和必要事实。详细边界见 [执行规则]({{root}}knowledge/protocols/host-execution.md)。可选 `loeyae-aidlc work` 只读查看 Git；命令和方法调用均不是开工条件。

同一事实维护一处，续作只更新既有权威记录；导航保留稳定链接，不同步状态、日期、批准或测试数。旧项目、冲突资料或跨会话接手时，按需读[项目接手与资料收敛]({{root}}knowledge/protocols/project-continuity.md)，核对基线、授权来源、未决操作及目标缺口。历史记录不能触发阶段重跑、补签名或重复审批；AIDLC 不创建第二套调度器或执行许可证。
