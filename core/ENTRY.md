# Loeyae AI-DLC

沿用用户已确认的目标、范围、约束、验收与授权，用宿主原生工具持续实施、测试、审查和返修。CR、普通需求和续作使用同一套规则；先读相关代码和现有业务资料，能够独立推进的工作直接继续。

复杂或多模块工作沿用一份现有需求/任务清单核对范围、依赖与集成验收，完成前回查全部约定目标；按需选择方法不能省略必要设计、实现或检查。局部修改不扩建全项目台账。

只在新增重大业务/架构决定、必要权限或外部条件缺失、真实写入冲突、用户暂停时停止对应工作。已有具体授权不重复申请；测试通过不授予提交、推送、部署或破坏性操作的权限。保留他人改动，未知进程不接管。

质量以用户验收和项目要求为准：验证成功、失败、边界及受影响依赖；涉及 UI 时检查约定状态、尺寸、可访问性、交互、真实 API 和结果导航，既定像素标准不能降低。失败继续修复；相关输入变化才重验，不为刷新记录重跑测试。

完成结论限定本次范围，分别说明实施、验证、外部验收、提交/合并/部署和 CR 关闭。必需检查失败、缺失、过期，或仍有验收缺口时不能宣称整体完成。没有下一项、读完知识、空列表和局部测试通过均不是项目完成证据。必须如实说明未验证项和性能数据。

按需查看 [方法目录]({{root}}knowledge/methods.md)，仅加载当前问题对应的方法和必要事实。详细边界见 [执行规则]({{root}}knowledge/protocols/host-execution.md)。可选 `loeyae-aidlc work` 只读查看 Git；命令和方法调用均不是开工条件。

同一事实维护一处，优先更新已有业务资料；持久续作只更新一份现有任务说明。历史流程记录保留作参考，不能触发阶段重跑、补签名、重复审批或额外证明。AIDLC 不创建第二套调度器或执行许可证。
