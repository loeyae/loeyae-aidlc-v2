# UI 页面语义规划

## 目的

在具体设计模式执行前，以需求、故事和存量证据建立可持久化的页面语义基线，供 HTML Mock 与 Figma 使用同一页面范围和产品语义。

## 职责边界

本文件只定义页面计划的输入、推导、产物格式和内容自检，不定义设计模式、工具、视觉样式、用户审批、state 状态或 I10 放行。

## 输入

- 已批准需求；
- 用户故事和验收标准；
- 工作区检测识别出的端与代码位置；
- 存量项目适用的逆向工程、路由、页面和组件证据；
- 已确认的角色、权限、业务状态和跨端流程。

缺少会改变页面数量、类型、字段、权限或操作路径的信息时，按 `common-question-format-guide.md` 提问，不得用假设补齐。

## 唯一产物

单模块路径：

`docs/aidlc/inception/ui-design/page-plan.md`

多模块路径：

`docs/aidlc/modules/{module-name}/inception/ui-design/page-plan.md`

页面计划至少包含：

```markdown
# UI 页面计划

## 页面清单
| ID | 端 | 页面名称 | 类型 | 来源 | 改造基础 | 目标代码文件 | 角色与权限 | 状态差异 |
|----|----|----------|------|------|----------|--------------|------------|----------|

## 页面内容契约
| 页面 ID | 可见字段/组件 | 输入与展示约束 | 条件可见性 | 来源引用 |
|---------|---------------|----------------|------------|----------|

## 操作闭环
| 来源页面 | 按钮/入口 | 目标页面或反馈 | 来源引用 |
|----------|-----------|----------------|----------|

## 跨端数据流
| 产生端/页面 | 数据或动作 | 消费端/页面 | 来源引用 |
|-------------|------------|-------------|----------|

## 未决项
无
```

“页面内容契约”必须记录用户可见的表单项、列表列、详情字段、提示/反馈和关键组件；输入格式、必填/只读、枚举、脱敏、空态等约束写入“输入与展示约束”。不得写视觉样式或实现细节。

类型只能取：

- `新增页面`；
- `局部改动`；
- `新增弹窗`。

局部改动必须填写已读取验证的改造基础和实际目标代码文件；新增项的目标代码文件写“待 Construction 确定”。

## 推导流程

1. 从需求和故事提取端、角色、入口、状态、操作和结果页面。
2. 存量项目读取实际路由、页面和组件，确认新增或局部改动。
3. 为每个页面记录稳定 ID、来源、权限和状态差异。
4. 为每个页面记录可见字段/组件、输入与展示约束、条件可见性及来源引用。
5. 为每个按钮和入口记录目标页面、弹窗、外部动作或原地反馈。
6. 记录跨端数据的产生方和消费方。
7. 合并仅字段或状态不同的重复页面，以状态差异表达；产品语义不同的页面不得合并。
8. 将无法确定的内容写入“未决项”，不得生成虚假结论。

## 内容自检

- 每个涉及的 FR/US 页面场景都有计划项或明确不适用依据；
- 页面 ID、名称和来源唯一且稳定；
- 每个页面的可见字段/组件、约束和条件可见性完整且可追溯；
- 局部改动均有读取证据；
- 角色权限和状态差异可追溯；
- 所有入口、按钮和跨端动作形成闭环；
- “未决项”为“无”时才可提交编排层请求用户确认。

## 禁止行为

- 不读取现有页面就判定存量页面类型；
- 用页面计划引入未经批准的产品功能；
- 为每种状态复制结构相同的完整页面；
- 写入 HTML/Figma 路径、nodeId、工具能力或视觉样式；
- 在本文件内批准页面计划或修改 I9/I10 状态。
