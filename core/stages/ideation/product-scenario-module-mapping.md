# 场景分析与模块映射

**职责**：在 I5 前确认场景边界、主次模块和跨模块挂接关系，登记在途 PRD，并维护场景装配清单。模块级 I5-I10 产物仍是需求基线，本文件只定义跨模块场景视图。

## 执行条件与路径

I3 始终执行。单模块项目跳过模块归属审批，但仍确认场景边界、登记在途 PRD 并生成装配清单。

| 项目类型 | 装配清单路径 |
|----------|--------------|
| 单模块 | `docs/aidlc/inception/scenario-manifest.md` |
| 多模块 | `docs/aidlc/product/scenarios/<scenario-id>/scenario-manifest.md` |

场景目录只保存 `scenario-manifest.md` 和条件产物 `prd.md`；I5-I10 产物按模块归档，禁止在场景目录复制需求、故事或页面规格。

## 执行步骤

| 步骤 | 内容 | 单模块项目 |
|------|------|------------|
| 1 | 接收并归纳用户描述的需求或场景 | 执行 |
| 2 | 确认起点、终点和明确不含内容 | 执行 |
| 3 | 基于 `product/modules.md`、系统基线和逆向产物给出主模块建议、次要模块清单、理由与备选方案 | 跳过 |
| 4 | 等待用户确认或修正模块归属 | 跳过 |
| 5 | 识别并登记在途或历史 PRD | 执行 |
| 6 | 生成或增量更新场景装配清单 | 执行 |
| 7 | 按步骤完成协议更新 state.md 与审计 | 执行 |

## 主模块判定

主模块是场景语义中心所在模块，按以下顺序判定：

1. 核心业务对象归属；
2. 不可省略的状态机归属；
3. 数据写入的权威模块，只读消费方不作为主模块；
4. 仍并列时选择预计 FR 数量最多的模块。

输出必须同时包含判定理由和备选方案。无法唯一判定时先建议拆分子场景并等待用户决定，不得自行猜测。

主模块执行完整 I5-I10；次要模块只执行被依赖切片，并通过 `product/contracts.md` 契约 ID 挂接。禁止创建覆盖全部模块的巨型 I5。

## 在途 PRD 登记

必须询问当前场景是否已有在途或历史 PRD。有则记录路径、版本、最后修改时间、编写方式、业务方回签及定位。

| 规则 | 约束 |
|------|------|
| R1 定位 | 在途 PRD 仅为参考资料，不是需求基线 |
| R2 覆盖方向 | 与 I5-I10 冲突时以 I5-I10 为准，不因此单独进入 CR |
| R3 禁止静默丢弃 | 在途 PRD 中未被 I5-I10 覆盖的语义进入 I5 澄清问题 |
| R4 已确认结论降级 | 缺确认人、确认日期或原文位置任一项时降级为待确认 |
| R5 时间戳留痕 | 记录最后修改时间，用于判断产物先后 |

## FR 编号与场景范围

跨模块项目使用 `<MODULE>-FR-<序号>`；FR ID 在模块内全局唯一且单调分配，序号不得按场景重置。单模块项目保持 `FR-<序号>`。场景归属只由装配清单维护，不编码进 FR ID。

## §8 来源定位键

语义类型仅允许 `状态 / 字段 / 权限 / 数值 / 枚举`。每条记录必须关联当前场景 FR，定位键在对应模块、语义类型和来源路径内唯一。

| 语义类型 | 固定格式 | 来源 |
|----------|----------|------|
| 状态 | `状态\|<对象>\|<源状态>-><目标状态>\|<触发事件>\|<前置条件>` | `data-model.md`；无前置条件填 `无` |
| 字段 | `字段\|<实体>.<字段名>` | `data-model.md` |
| 权限 | `权限\|<FR ID>\|<角色>\|<操作>\|<前置条件>` | `role-permission-matrix.md` |
| 数值 | `数值\|<FR ID>\|<约束名称>` | `requirements.md` FR/GWT |
| 枚举 | `枚举\|<实体或对象>.<字段或属性>\|<枚举值>` | `data-model.md` 或 `requirements.md` |

I5 生成状态、字段、数值和枚举定位键，I6 审查；I7 生成权限定位键，I8 审查。格式错误、范围内重复、FR 悬空或组成字段不足时阻断并回权威来源补齐。禁止使用行号、自然语言摘要或临时 ID。

## §9 来源版本与新鲜度

每个索引区块关联的每条适用来源路径独立一行。同一路径服务多个区块时按区块分别记录。

普通 Markdown 来源统一以原始 UTF-8 字节 SHA-256 作为修订标识，格式 `sha256:<64 位小写十六进制>`；同步时间使用 RFC 3339。禁止混用文档版本、Git commit、blob hash 或人工版本号。

| 状态 | 来源路径 | 修订标识 | 同步时间 | 依据 | 转换规则 |
|------|----------|----------|----------|------|----------|
| `current` | 必填 | 必填 | 必填 | 可选 | 重算哈希一致且索引已同步 |
| `stale` | 必填 | 已有来源保留上次值；新增来源填 `—` | 必填 | 必填 | 来源新增、删除、改路径、哈希变化或定位键变化时进入；同步并更新哈希后恢复 `current` |
| `not-applicable` | `—` | `—` | 必填 | 必填 | 仅合法不适用时使用；适用性变化时先转 `stale` 再建立 `current` 记录 |

新增来源不得直接标记 `current`。删除来源时保留原路径和上次修订标识并置为 `stale`，不得删除证据行。
