# 应用设计

未加载时先读[共用规则](../../knowledge/protocols/host-execution.md)，已加载则复用。

已有项目先核对适用规范、原设计和相关实现，继承现有技术栈、分层、契约、数据与测试惯例；本次需求需要调整时说明具体依据与影响。新项目按已确认约束选择方案。从本次范围确定变化的组件职责、接口、数据流、依赖及相关 NFR 和基础设施约束，复用已有能力。

影响业务或契约的关键未知按[定向澄清](../../knowledge/protocols/design-clarification.md)处理；涉及接口、数据、安全或配置时查[工程检查](../../knowledge/protocols/engineering-checks.md)。按已有授权自主选择，超出决策范围的重大新架构取舍才请求用户决定。

在原设计或任务清单中，将本次业务增量关联到原目标/AC、实现入口、共享契约、真实依赖和验证方式；核对已有验证命令、环境及数据前提，保留尚未具备的条件。需要拆分时使用[任务拆分](../aidlc-unit-generation/SKILL.md)，不为简单变化另建完整设计文档，图示有助理解时优先 Mermaid。

约定范围包含实现与验收时，设计足以支持当前增量后直接推进该项实现和验证；后续设计按实际依赖补充，不等待整份设计统一批准。仅设计任务交付设计及其真实未决项。
