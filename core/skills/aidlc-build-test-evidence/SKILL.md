# build-test-evidence

从项目脚本、配置和现有测试确定真实命令；不因调用方没填写命令矩阵就停止，先读取仓库查明。按[验证顺序与复用](../../knowledge/protocols/verification.md#先短回归再集中核验)先用短回归判断本次改变，出现决定性失败就停止对应试验的依赖工作、定位修复，独立工作继续。复用已有工具及仍适用的结果，按影响补必要构建和集成验证；不要求审查先通过，只有广泛影响或明确交付要求才全量。

执行前按 [真实验证](../../knowledge/protocols/verification.md) 限定读取、扫描与输出，产出物和依赖从明确入口定位；语义变化沿既有 STORY/AC 查全受影响用例及前置依赖，不沿用旧编号范围作为边界。保留命令、退出码、关键输出和未验证项，明确选定检查与完整套件的区别。文档、生成源和合并后的复验按实际影响判断，不按文件扩展名豁免业务检查；短回归通过不替代最终目标核对和项目必需验收。

不手工编造通过结果；无法运行时说明真实环境缺口并继续可做的检查。默认不创建证据命令清单、签名 JSON、无行为证明或额外测试汇总文档。

默认由宿主执行，结果和必要业务文档是工作依据；共享边界见 [宿主执行协议](../../knowledge/protocols/host-execution.md)。


涉及接口、数据、安全或配置时按需读取 [工程检查](../../knowledge/protocols/engineering-checks.md)。

所有结论遵循 [统一完成判定](../../knowledge/protocols/completion.md)，未知、失败、过期和外部待办不能省略。
