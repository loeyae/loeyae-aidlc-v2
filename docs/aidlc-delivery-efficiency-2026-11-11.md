完整复用键至少涵盖：命令及选择器、执行输入与测试内容、依赖/构建测试配置、工具链和适用环境、工作树身份、阶段类型、执行器依赖闭包。时间敏感的服务、数据库和外部观察沿用其有效期与环境边界，不能用本地文件摘要代替当前环境事实。

同一观察可被多个单元引用的前提是命令与覆盖本来就同时包含它们；每个单元分别核对其 UC-D 和实际回归要求。不同命令的包含关系暂不推断。对于会修改数据库、共享报告目录或外部状态的命令，先保证独占资源和副作用可核对，不能把去重当成允许并发的依据。

旧签名、执行时间及未通过记录全部保留。新核验必须显式引用原观察并说明是复用；不能把核验时间写成新测试执行时间。旧版本没有完整可验证观察时，不自动升级为新版本通过。检查器升级也不默认兼容：新的解释规则必须重新判定其证据需求与结果。

### 验证矩阵与性能口径

先用隔离短夹具覆盖以下正反例，再运行一次相关集成检查；不让商城整链承担框架自测。

| 场景 | 必须观察到的结果 |
|---|---|
| 注入 canonical I13 / CR 参数混用、错误工作树或报告根 | 调用业务测试前给出具体诊断，无整链重试 |
| 修改已声明的其他模块私有文档；随后改为实际共享输入 | 前者局部执行摘要不变；后者变化且相关观察失效 |
| 改共享校验器/接口/迁移；新增一个没有 UC-D Tag 的直接相关测试 | 受影响消费者及该测试入选；无关单元仍被排除 |
| 只改发布/路径适配，再修改真正执行的 runner 或测试输入 | 前者无业务命令重跑；后者只重跑依赖它的命令 |
| 两个单元引用完全相同命令；随后改变环境、选择器、phase 或依赖 | 首次实际执行一次、分别核验；任一键变更拒绝错误复用 |
| 篡改输出、缺失来源、未声明检查器依赖、旧格式观察不完整 | 不得生成可用的当前核验或阶段通过 |
| 提交时遇到 heartbeat/revision 冲突 | 只重试提交，不重跑测试或审查 producer |
| 正式验证前后分别修改相关测试、纯进度说明 | 相关测试修改重验；纯进度说明不触发业务重跑；真实业务文档输入变化仍重验 |

复用现有 `test_delivery_efficiency.ts`、`test_functional_checker_identity.ts`、`test_audit_semantic_phase_reuse.ts`、`test_validation_revision_scope.ts`、repair/session 回归与项目 CR 参数夹具，按实际改动补缺失反例。规则与安装检查不等于真实模型的业务交付验证。

从现有命令/producer 日志提取：实际启动次数、命令执行时间、身份/来源核验时间、阶段发布及锁等待时间、人工/外部等待、无关输入失效次数、因工具适配导致的整链重跑次数、唯一用例数与映射执行数。命令并行时不将时长相加充当墙钟时间；无原始时间的区间保持未归因。不要为统计要求逐命令新增手工文档。

工程验收目标为：短夹具中的“同键重复命令启动”“已知无关文档触发局部测试失效”“仅适配/发布变化触发业务整链重跑”均为零；同时所有真实相关变化、覆盖不足和篡改反例都必须触发验证或拒绝。业务目标按后续同范围样本衡量控制开销和总经过时间；首个样本完成前只报告工程改善，不报告商城提速比例。
