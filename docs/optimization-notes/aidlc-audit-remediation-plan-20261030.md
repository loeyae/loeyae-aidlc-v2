本计划修复 2026 年 10 月 30 日审计确认的错误放行、并行隔离、风险路由、门禁及发行问题，并补齐实际 Agent 任务评测、安全验证和项目交接约定。按依赖顺序实施，完成一项记录实际变更与验证结果。

## 修复范围与验收用例

### RP00 测试隔离

保留用户原有源码和 Codex 分发改动。测试在独立临时项目内操作 state、claims 和证据。安装生命周期测试会重建分发，必须在独立仓库副本执行，或与构建及打包串行；不得在共享源码目录内并发运行这些操作。

现有审计反例转换为仓库回归。只对行为和风险变化增加测试，文档修正使用结构及引用检查。

### RP01 审查证据

主要范围：`core/tools/aidlc-semantic-checks.ts`、`aidlc-evidence-policy.ts`、`aidlc-orchestrate.ts`、审查 sensor 与阶段规范。

分别解析 Spec 和 Standards 的明确结论；缺失、失败、未知或相互矛盾的结论均不得产出通过证据。保留建议级开放问题的既有计数契约。

审查文件使用项目相对路径和已解析源码根，支持 `core/`、`bin/`、`packages/` 等真实布局。覆盖分母取当前模块或单元的适用变更集，不能仅要求文件数组非空；删除与重命名结合 Git 变更类型判断，不把已删除文件误判成虚构文件。范围不能可靠确定时给出明确诊断，保留保守检查。

验收至少覆盖：两个轴分别失败、失败与通过并存、单轴缺失、无结论、未审查的新增文件、不存在的文件、非默认源码根、重命名、删除、无关单元变更及来源漂移。生产者、sensor 和 report 的判断保持一致。

### RP02 并行工作区

主要范围：`core/tools/aidlc-worktree-light.ts` 及 worktree 回归。用独立文件复制替代普通文件硬链接；保留已有 symlink 边界检查和完整 checkout 回退。

同时保留两个 warm 工作区，对其中一个执行原地写、追加、截断和替换。缓存及另一工作区的内容和 Git 状态必须不变。缓存损坏或基线变更时沿用安全回退，不删除仍在使用的工作区。

### RP03 风险路由与安全验证

主要范围：阶段选择、execution profile、condition 构造和 workflow-plan 解析。根据已确认风险计算必要阶段及其依赖，统一供实际执行、stage plan 和 rule load plan 使用。升级保持单向，保留轻量任务的适用性判断。

skip 必须有非空依据；新接口、跨服务、架构或安全边界等必需风险不得被普通 skip 覆盖。安全风险派生实际适用的验证要求，复用项目工具；缺少必要工具时给出未验证诊断，不强制给所有项目引入同一组扫描器。

验收包括带安全风险的 bugfix、跨服务变化、空理由 skip、与风险冲突的 skip、合法局部修复、不适用 NFR、升级后的依赖闭包，以及计划与真实 directive 一致性。

### RP04 全局审查

在现有单元双轴审查之外，将多单元、跨边界及高风险触发的全局审查变成受控证据要求。优先复用当前编排和证据发布机制，不引入固定 reviewer、强制多代理或额外业务审批。

全局结论须覆盖本次选定单元、跨单元契约和影响范围，并绑定相关来源及单元审查结果。缺失、失败、遗漏单元、开放关键或重要问题及相关输入变化均阻断进入 C8；未触发的简单单元任务保留明确不适用依据。

存量工作流缺少新增验证字段时，提供定向补验证路径，不伪造历史通过，不静默放行。纯时间经过不要求重做仍有效的内容绑定观察。

### RP05 部署验证与项目交接

主要范围：operation 阶段、部署技能、受控命令及验证门禁。登记实际交付配置路径、目标类型和摘要；从受允许命令取得成功执行结果，并绑定来源。失败、未执行、配置漂移或遗漏配置均阻断完整通过。

验证只应用于实际选择的部署目标，不固定要求 Docker、Jenkins 或 Kubernetes。保留部署授权的人工决策边界。将两个技能的 `operations.md` 引用更新到拆分后的阶段文件。

部署指南明确制品、验收责任、发布前提、smoke test、迁移及回滚，以及部署后交接责任。文档中的角色和环境依据项目实际信息填写，不自行授予部署权限。

### RP06 指令一致性

统一 `core-workflow`、state-template、continuity、token 管理、提问指南及防护指南。唯一控制面为当前 Markdown state/audit；handoff 是派生视图。

宿主可使用其支持的聊天或结构化提问。问题文件用于批量或需要持久化的问题，不要求将有效自然语言答案重新转为字母。普通 notify 阶段复用已有授权，block 阶段仍需要明确审批；必需质量门禁不因用户要求赶进度而失效。

旧 JSON 状态仅在明确的迁移或历史说明中出现。新增引用检查覆盖技能指向的已删除文件。

### RP07 TAP 解析

支持测试汇总完整且合法的零文件覆盖率表。测试计数来自同一次真实运行的 TAP 汇总，覆盖率表不能改变通过、失败或 skipped 数。

保留对截断、重复头、重复汇总、未知尾部、失败与成功数矛盾的拒绝。使用项目可用且声明支持的 Node 版本验证，记录实际运行版本。

### RP08 回归修复

逐项分类已有失败：session 或精确实例夹具缺失、断言与已批准契约不一致、实际实现缺陷、环境不可用。仅在验证契约已确定后调整旧断言；不通过删除测试、跳过关键场景或降低门禁获得全绿。

夹具复用 session helper，执行 inspect/bind 或直接受控夹具绑定，保留失效 binding、其他会话及错误 instance 被拒绝的负例。Python 路径使用进程级配置，不写全局环境。失败后先复测必要范围，最终才运行完整清单。

### RP09 分发与发布验收

从同一源码快照生成九个平台分发。构建、分发校验、tarball 打包、实际安装及安装后验收串行使用该候选快照。安装回归不改写待打包目录。

依次验证：阶段图、类型、完整核心回归、本地 Provider、九平台构建、分发字节一致、tarball 内容和依赖、隔离安装后 CLI 与流程行为。发布需要同一份候选的完整证据；构建成功不能替代安装后验收。

### RP10 Agent 任务评测

评测任务覆盖局部 bugfix、风险升级、多单元协作、会话接管、上游变更失效及部署准备。每项任务给出输入、可观察终态、禁止错误放行的反例及采集方式。

分别记录确定性引擎回归与真实宿主 Agent 的运行结果。实际任务可按需要重复试验，记录完成情况、误放行、人工修订、耗时及工具使用；只记录真实观测，不设置未经测量的通过率目标。宿主执行者、模型和代理数量由宿主选择。无法连接的宿主保留未验证状态。

## 本轮已落地的实现

- 审查：分别验证 Spec、Standards 的明确结论；拒绝缺失、未知、失败或矛盾结论；以真实文件和交付范围核对审查覆盖，沿用严重度分区计数。
- 并行：warm 工作区普通文件采用实体复制，避免原地写入污染缓存和其他工作区。
- 风险：安全、未知边界、架构、外部契约及迁移等已记录风险补齐适用阶段；非空 skip 依据不能覆盖必需风险。安全风险在 C8 绑定项目验收来源与实际 test/check 命令。
- 全局审查：多单元或高风险要求 FINAL_GLOBAL；只读输入投影提供实际范围，受控证据绑定所有单元审查、相关代码、需求、清单、契约及删除声明；C8 准入和完成复核。
- 部署：实际配置与同 id 的允许 check 命令绑定，配置漂移或执行失败不能沿用旧证据；补齐发布责任、smoke test、迁移与回滚交接。
- 指令：统一 Markdown state/audit 控制面，修正过期阶段引用和宿主提问规则；摘要与 handoff 是派生视图。
- 实施中发现的实现缺陷：恢复 I13 真实来源覆盖生产链；保留 payload 的数组 `inputs`，将阶段指纹分开保存；刷新复用核对 workflow 身份、checker 命令及有效期；只读路由检查不取得会话写权限。
- 精确会话路由：多个单元持有同名阶段 claim 时，report 按当前 binding、unit 和 instance 选择目标；验证 Web 报告不修改 API 单元的 claim、current 或历史。C8 的 next 与 report 都执行跨模块屏障，session binding 不授予跳过屏障的权限。

已新增七个针对性测试文件：`test_audit_review.ts`、`test_audit_worktree_isolation.ts`、`test_audit_routing.ts`、`test_audit_global_review.ts`、`test_audit_deployment.ts`、`test_audit_security.ts`、`test_audit_maintenance.ts`。这七个专项已在最终冻结运行时上通过；真实宿主 Agent 试跑仍独立记录。
