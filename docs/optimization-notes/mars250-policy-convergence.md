# MARS-250 validation policy convergence

Baseline: `main@0533c152eb175d027bb0dc05c457a88456261e43` / 4.22.2. This change builds on MARS-249; its original directed regression remains required. No version change, tag, release or main integration is part of this issue.

| Requirement | Implementation and evidence | Compatibility and limits |
| --- | --- | --- |
| Static freshness | Shared `CONTENT_BOUND_EVIDENCE` policy covers the existing historical observations and deterministic local sensors. Actual frontend and template producer outputs remain accepted at 25h by the main gate and reuse planner. Changed source, checker command, provenance and invalid/future dates are rejected. Attestation uses the same time policy; explicit max age still tightens it. | Recovery and unknown sensors keep 24h. Explicit external freshness windows remain binding. Local diagram/UI contract checks do not refresh remote Provider sessions or credentials. New semantic checker records have `command_version: 2` and exact command binding; old records retain the original provenance/digest validation. |
| Actual frontend mappings | Producer and gate share `aidlc-frontend-platform.ts`. They read actual existing mapping tables, validate names/targets and platform declarations, compare applicable approved design/platform rows, and reject omitted/duplicate/placeholder rows. A real 1-layout/2-component/1-constraint page passes, including public `orchestrate report`. | Existing Markdown tables remain supported. Optional `design_source`/`platform_source` references select existing unit/page sections; narrowing page design does not drop independent platform constraints. Old generated placeholder evidence must be regenerated. A historical project without design sources gets an explicit `legacy-spec-tables` basis, not a requirement to document unrelated components. Pure Web routing is unchanged. Prose-only constraints that cannot be parsed need applicable tables in existing documents, with no new approval artifact. |
| Alternative observation cache | RED/GREEN and applicable C8 checks use validated module/unit evidence scope, shared contract paths and transitive declared dependencies. Input/environment binding is checked by phase/C8 gates as well as the producer. Unrelated declared-private files do not rerun; own/shared/dependency/lockfile, command/cwd, applicability, baseline generation and relevant environment changes do. `reused_from` preserves the original `observation_id`. Mutating checks cannot seed reusable cache entries. | Unknown files remain included; absent ownership uses explicit `conservative-worktree`. Environment defaults to all variables except the session publication token. Optional command `evidence_inputs.environment` declares a complete relevant-variable contract, supplemented by execution-discovery variables and Node identity. Values are hashed; the cache records mode/key names. Authors must include actual command dependencies; narrowing is not inferred from command text. Old cache format misses and executes again. |
| Approval authority | Code generation planning, result template, audit instructions, summary and completion criteria now follow the graph/directive policy. `notify` reuses existing authorization; explicit user review requests wait. | Architecture and Operations authorization remain `block`. No graph gate was downgraded or notify upgraded. |
| Delivery/observability scope | Construction code generation/review only checks artifacts and observability required by selected requirements, approved deployment decisions and existing delivery scope. Libraries/local tools without those needs have no extra deployment or monitoring obligation. | Operations planning/authorization remain conditional. Required deployment/observability artifacts and policies still get checked. The workflow stops at implementation delivery/deployment preparation and authorization, without automatic production deployment or post-deployment operations. |
| Test traceability scope | TDD and review use selected requirements, observable behavior and actual impact. Existing suite/method `uc_mapping` is valid without retrofitting annotations or testing every public function. The actual CLI fixture reuses an unannotated suite, runs a real assertion, accepts complete mapping and rejects missing selected UC-D coverage. | Existing RED/BASELINE/GREEN coverage and execution-status gates remain. Unaffected historical/tool tests need no annotation. A prose statement or tag scan cannot substitute for executed selected coverage. No-behavior scope still needs trusted I13/exemption and real alternative validation. |

The sensor inventory and TTL rationale live with the runtime contract in `core/knowledge/protocols/common-quality-gates.md`. Sensor contracts, Construction prose/templates and the CLI/user guide use that policy. All nine harness distributions are regenerated and checked for byte parity.

Validation is recorded in the issue's attached `validation-results.json` and individual command logs. The directed checks include `test_mars250_policy`, the original `test_mars249_validation_policy`, Construction phase gates, attestation, Operations conditions, execution policy, scoped source binding, reuse planning, UI freshness and distribution parity, plus typecheck and the distribution build.

Clean baseline typecheck separately reproduced TS2307 for `dompurify` and `mermaid`: their imports existed in baseline source, but neither package is present in the lockfile. The minimal fix resolves these optional runtime capabilities by variable names, preserving the existing `not_executed` fallback when absent. No package or lockfile dependency was added; current typecheck passes. This does not claim Mermaid parsing executed in a lockfile-only installation.

Repository protection: implementation, independent lockfile dependency installation, build and tests run in the MARS-250 worktree. Main's original `.gitignore` modification is preserved; `AGENTS.md` was absent on entry. Main branch/HEAD, staged/unstaged state and all pre-existing worktree registrations are compared with the entry snapshot before delivery. Shared Git writes use the local directory serial lock.
