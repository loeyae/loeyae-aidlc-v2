# M02 AI DLC 质量门禁优化落地清单

日期：2026-10-14。依据：`m02-aidlc-交开发质量门禁优化-20261014.md` 及当前框架评估。代码核对基线：版本 `4.15.0`，提交 `39a0399`。

本清单用于实施框架级门禁优化：先让缺证据、规则冲突和过期结论真正阻断，再补齐跨产物检查和度量。M02 原始业务产物不在当前仓库中，具体业务问题的修复状态需在对应商品项目复核。

下文“新增”检查器、错误码和证据字段均为拟实施契约，不代表当前 CLI 已支持。当前已存在的检查器包括 `traceability-matrix`、`ui-artifact-consistency`、`inception-consistency`。不新增与现有工作流平行的审批体系。

## P0 必须先落地的阻断能力

| P0-03 字段能力与方案验证 | 1；决定字段落点前及故事准入 | 新增 `field-capability`；机械核对覆盖与来源，技术审查或验证报告证明能力 | requirements 中的字段矩阵；实体/表、DTO/VO、转换、查询/索引、导入导出、国际化、实际消费者的代码定位及版本；新建能力的原型/执行结果 | 适用字段漏登记 `FIELD_UNCOVERED`；必需能力未核实 `FIELD_CAPABILITY_UNVERIFIED`；方案与证据不符 `FIELD_PLAN_CONFLICT`；缺必要性能验证 `FIELD_PERFORMANCE_UNVERIFIED` |

| P0-05 HTML 静态校验 | 3；HTML 生成准出及 I10 | 在 `ui-artifact-consistency` 的 HTML 路径接入真实 HTML validator 和确定性 DOM 检查；I10 重验或消费仍有效的证据 | canonical manifest 全部最终 HTML、校验器配置及版本、实际执行日志、规则清单、文件摘要；使用本地校验，避免向公共服务上传业务 Mock | ERROR 大于 0 `HTML_STATIC_ERROR`；命令失败/未执行 `HTML_VALIDATOR_UNAVAILABLE`；重复 DOM ID 等约定违例 `HTML_DOM_CONTRACT_ERROR`；报告不是当前 HTML `HTML_REPORT_STALE` |
| P0-06 区域级故事及 AC 追溯 | 3；HTML 生成准出、I10 | 扩展 `htmlArtifactContract()` 及 `ui-artifact-consistency`；用 DOM 解析替代仅统计正则；Figma 通过节点映射实施等价检查 | page-plan 的功能区域目录、差异清单、HTML DOM 或 Figma 节点、canonical manifest、当前 Story/AC 索引、AC 隶属关系 | 新增/改动区域无映射 `UI_REGION_UNTRACED`；只标页面根容器 `UI_ROOT_ONLY_TRACE`；ID 悬空 `UI_TRACE_TARGET_MISSING`；AC 不属于所标故事 `UI_AC_STORY_MISMATCH` |

| P0-08 变更后失效与定向复验 | 4；用户决定、技术反馈、接口事实或正文变化时 | 扩展 `aidlc-ui-governance.ts` 的影响矩阵/checkpoint；通用证据绑定补齐非 UI 产物；由 conductor 更新 workflow 状态 | 变化前后正文及摘要、变化 ID、受影响产物/消费者、有效决定替换记录、代码基线判定、已完成检查及复验记录 | 变化无法分类/映射 `CHANGE_IMPACT_UNMAPPED`；旧结论仍被消费 `CHANGE_EVIDENCE_STALE`；缺同步或复验 `CHANGE_REVERIFY_MISSING`；已存在代码基线却绕过应走的 CR `CHANGE_ROUTE_INVALID` |
| P0-09 交开发就绪汇总 | 5；I10 产品/UI 就绪汇总及实际开发准入 | 扩展 `inception-consistency` 聚合 P0 证据；实际开发准入重验当前摘要及既有依赖门禁；新增派生交付状态，不覆盖原有阶段状态 | 当前交付范围、全部适用专项 evidence、开发交接清单、有效/废止决定、待确认项及阻断级别、已完成适用阶段；交付包文件摘要 | 任一适用检查失败/未验证/过期 `DELIVERY_GATE_NOT_READY`；阻断待确认项未关 `DELIVERY_BLOCKER_OPEN`；交接包缺项 `DELIVERY_PACKAGE_INCOMPLETE`；后续阶段门禁未满足 `DEVELOPMENT_ENTRY_NOT_READY` |

P0-02 的关键依赖范围必须先从需求中的入站数据、外部动作和消费者盘点得到，不能只检查作者主动登记的几条依赖。非关键待确认项允许保留，但必须说明未进入当前交付范围及其影响，不得以推测替代已确认结论。

P0-03 将“基座已支持”和“拟新增实现”分开记录。现有基座缺少能力并不必然阻断：若需求明确增加该能力，已有可复核技术验证和消费者适配方案，可以通过；不能把尚未实现的能力写成已存在。双语字段名、字段值、枚举文案分别验证，性能要求以业务阈值和可复现测量为依据。

P0-04 不把前端不可达等同于接口不需防御。例如“草稿不可勾选”和“接口拒绝含草稿请求”可以同时成立。未发现冲突但缺少语义审查证据，也不能视为检查通过。

P0-06 先从批准的页面内容契约建立区域全集，再核对 DOM/节点映射，不能只以已标注区域作为分母。HTML 建议使用稳定区域 ID，与 `data-change`、`data-us`、`data-ac` 对应；纯装饰区域可有说明地排除。移除项在差异清单保留区域、故事和 AC 映射，检查最终页面确实不存在；不要求把已移除控件重新插入最终 DOM。

P0-07 的显示、禁用和隐藏由批准的产品规则决定。返回、取消等局部动作按适用性记录结果；不强制编造网络失败路径。HTML 可直接运行的交互以浏览器验证补充证据；仅展示交互说明的 Mock 以操作表和设计审查验证，不把原型当作生产接口实现。

P0-08 在 P0 先保证每次变更都会登记影响并使旧证据失效，允许通过受控人工影响登记实现全产物覆盖；P1 再加强遗漏发现。保留现有一次全量验收与定向复验机制，不因每项新检查再启动一轮全量验收。无关模块导致 upstream 指针前进不应使本模块失败。

| 编号及改动 | 涉及门禁和时机 | 检查器改动 | 输入证据 | 阻断条件及拟定错误码 |
| --- | --- | --- | --- | --- |
| P1-01 Story 与 AC 定义及副本对账 | 2、4、5；故事准出及更新后 | 扩展 `story-rule-consistency` 的确定性检查；共享 Story/AC 解析器 | 主故事、实际存在的 Epic 副本、AC 定义索引、版本摘要；定义与引用分别分类 | 重复定义 `STORY_DEFINITION_DUPLICATE`；副本语义正文不同 `STORY_COPY_DIVERGED`；AC 归属缺失 `AC_OWNER_MISSING`。重复引用同一 ID 不算重复定义；没有副本的项目不要求新增副本 |
| P1-02 字段与决定的跨产物对账 | 0～4、5；字段/决定变化及交付前 | 新增 `artifact-consistency`；在 P0 聚合中接入该证据 | 带粒度的字段稳定 ID、合法别名、有效与废止决定、REQ/Story/page-specs/差异清单/Mock/交接清单映射 | 活跃产物仍采用废止规则 `ARTIFACT_SUPERSEDED_RULE_USED`；字段粒度或定义冲突 `ARTIFACT_FIELD_CONFLICT`；映射悬空 `ARTIFACT_MAPPING_MISSING`。历史审计引用和明确的迁移说明不按残留误报 |
| P1-03 全产物变更遗漏检测 | 4、5；变更处理与恢复就绪前 | 扩展影响图和 `artifact-consistency`，复用 P0-08 的失效链 | old/new ID 与摘要、产物引用图、页面/字段/消费者依赖、同步结果、复验结果；I13 已产生时包含 UC-D，其他下游按实际生成情况纳入 | 应受影响产物未登记 `CHANGE_ARTIFACT_OMITTED`；声明同步但仍保留旧语义 `CHANGE_SYNC_INCOMPLETE`；新依赖未入图 `CHANGE_DEPENDENCY_MISSING`。新增/删除 ID 同时使用旧、新映射，避免删除后影响消失 |

自动对账优先比较结构化规则及稳定引用，再将疑似自然语言冲突送语义审查。术语命中、字符串不同和文件修改时间不能单独证明业务矛盾或同步完成。无行为的排版变更无需重做业务审查，但其新文件摘要仍须有受控记录。

## P2 度量和持续改进

| 编号及改动 | 涉及门禁和时机 | 检查器或工具改动 | 输入证据 | 阻断条件 |
| --- | --- | --- | --- | --- |
| P2-01 交付与回流质量度量 | 5；每次交付及后续回流登记 | 新增只读质量汇总工具，不新增业务准入 sensor | 交付 ID、有效 evidence、交付时间、回流缺陷 ID、原因分类、首次可发现阶段、外部事实确认时间及版本 | 指标数据缺失只标为未知，不阻断业务交付。业务阻断仍由 P0/P1 有效证据决定 |

度量口径：HTML ERROR、未裁决冲突、阻断待确认项必须为 0；区域追溯覆盖率的分母为本次全部适用新增/改动功能区域；高风险规则覆盖率的分母为已识别规则全集。分母为 0 时记“不适用”，不能虚报 100%。分别统计语义错误、同步遗漏、技术可行性遗漏、外部事实后续变化；一个缺陷跨多页只按同一缺陷 ID 计数，并保留次要原因。

## 统一输入与证据契约

优先扩展现有 requirements、user-stories、page-plan、page-specs 和交叉验证报告中的结构化章节。开发交接清单是交付索引，不复制所有业务结论。若需要机器清单，须指定唯一权威来源和确定性投影方式，避免 Markdown 与 JSON 各自维护一份事实。

每项专项 evidence 在现有受控 producer/provenance 之上增加以下业务字段；最终字段名须与实际证据封装协调后定稿：

| 字段组 | 要求 |
| --- | --- |
| 身份与适用性 | workflow 标识、module、stage、scope、真实 UI route；逐检查项的 applicable 和判定依据 |
| 输入绑定 | `inputs[]` 中记录路径/来源、SHA-256、代码 revision 或接口版本；含未提交代码时记录实际相关文件摘要；最终 HTML/节点证据也纳入绑定 |
| 执行来源 | checker 名称/版本、配置摘要、producer execution ID、实际命令/退出码/日志摘要；语义审查记录的内容摘要和审查者身份 |
| 检查范围 | 检查的依赖/字段/规则/区域 ID 全集；应检查数、实检数、遗漏列表及带理由的排除项 |
| 检查结果 | 每项结论、错误码、来源定位、开放阻断项；失败或未验证不得投影成 passed |
| 审查补充 | 技术结论引用代码/能力验证；语义结论引用双方规则、边界示例及裁决；不能只写“通过” |

沿用现有系统的受控证据封装与状态约定。专项未完成或能力不可用时记录未验证诊断，不伪造通过证据；`not_applicable` 只能基于真实适用性判断。已验证证据输入变化后立即失效，重跑或追加受控复验；仅过了一段时间不等于事实改变，具体有效期沿用或明确扩展现有政策。

语义审查是证据来源，检查器负责验证其范围、输入绑定、结论与未决问题。普通确定性 checker 不能仅靠正则或 ID 存在性证明任意自然语言公式正确。默认自动执行审查；只有业务决定冲突或无法判定来源优先级时才请求产品裁决，不为每个字段新增人工审批。

交付状态按当前范围派生：有失败、缺证据、阻断待确认项或过期证据时为“待交付”；已就绪但新事实推翻方案时为“需回流”；全部适用证据通过时为“产品与 UI 可交开发”；实际进入“开发实施中”还需开发接收及后续适用工作流门禁。不同模块可以有不同就绪状态，不以一个模块的证据放行其他模块。
