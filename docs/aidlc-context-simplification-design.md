# AI-DLC 过程文档与上下文精简设计

日期：2026-11-11。依据商城 `dfi-mall-kiro` 的只读盘点：5,973 份 Markdown/JSON 共 229.1 MB；活动状态/审计 50.3 MB；m19 验证目录 61.4 MB。文件体积不是实际模型 token 使用量，也不证明所有文件都被读入会话。

## 事实纠正与目标

抽查三模块 audit 的 Session Claims、Instance Owners、Active Instances 占约 95%–97%。m19 的 158 份 command.json 共 37.1 MB，主要负载是来源哈希映射。根 handoff 的 m02 旧阶段与当前 done 状态不一致。当前切片目录同时保存历史对象，不应递归加载。

上一轮将 m01/u03、m19/u06 私有视图为空列为疑似覆盖缺口；复核发现其 inherited 分别承载约 147 KB、154 KB 的共享需求/故事。应修正为“索引/阅读入口未清楚展示继承”，不能据私有空文件认定业务信息缺失。现有 checkSlices 已负责完整映射校验，复用它，不再建立另一套完整性门禁；本轮未重验商城切片门禁。

目标是减少默认读取、重复状态记录和机器数据输出，同时保留全部批准需求、共享依赖、UI 验收、原始证据、历史 RED 和当前质量门禁。不得用文档大小阈值判定业务失败。

## Core 与宿主边界

Core 提供精确 workflow/module/unit 的只读续作视图、真实来源标识、受控读取计划和机器校验；当前事实仍使用现有 legacy/facts 存储及 session binding，不另建状态。

宿主自行选择模型、上下文组织、文件读取和分页策略。Core 的视图不签发授权、不自动转交、不证明门禁通过。运行授权期限和预算保持不变；本轮不新增 Supervisor、调度器或强制上下文台账。

## 数据与行为契约

1. `orchestrate state context [--module <id>] [--unit <id>]`（集成使用互斥的 `--integration`）：只读取目标工作流及必要 registry/global 身份，返回当前目标、revision、状态、精确目标的领取摘要、最近五项相关报告和下一步命令。省略 session binding、完整历史、全量实例列表与 audit 正文。未给模块时不自动选择并行模块。已完成视图不等于全部质量门禁通过。facts 模式明确指向事实文件，展示 Markdown 缺失不要求重建；未执行 I14 时兼容既有 default 单元，已完成 I14 却缺 manifest 不假造默认单元。
2. `orchestrate state artifact --path <relative> [--offset <字符偏移>] [--limit <字符数>]`：过程产物的只读阅读接口。Markdown 有界分页，返回内容 SHA-256、范围及下一页位置；JSON 默认只投影结果字段及被省略字段名称，不展开哈希表、环境或原始命令日志。仅访问公开 docs/aidlc 与 .aidlc/evidence/reports，拒绝逃逸、链接与私有控制状态。它不是新验证器，也不改原始证据格式。
3. STATE_UPDATED 审计新增格式为增量：保存 workflow/revision/current/status、变化的领取身份前后值和 handoff 摘要。无关领取不重复复制；授权及批次字段变化继续记录。旧 audit 原字节保留，现有专门领取/审批事件继续保留。
4. 现有 BusinessDocumentLoadPlan 增加阅读说明：私有/继承文件角色、每文件体积、覆盖计数和“按当前 manifest 精确路径读取”的策略。不改 generator v1 的 canonical 对象与 manifest 身份，避免仅改善索引就让存量全部切片证据失效；动态读取视图展示 inherited 与 private 的并集，不要求重生成。
5. Skill、续作提示和各 Harness 入口统一先看 context/next preview，按 rule_load_plan/business_document_load_plan 读取。历史 audit、branch-snapshots、history、未被当前 manifest 引用的 objects、验证全目录和多份状态展示不再作为默认加载项。保留按具体故障查阅的入口。

## 实施顺序与验收

| 批次 | 实施 | 验收 |
|---|---|---|
| C1 | 只读 context 与公开 artifact 阅读接口 | 精确单/分模块、无会话可读、不读取兄弟状态、无写入；分页可拼回原文；JSON 大映射默认不输出；路径/链接拒绝 |
| C2 | 增量审计 | 普通状态更新输出不随无关 claim 数量线性增长；续租/转交/释放身份变化可追溯；历史前缀原样保留；既有会话回归 |
| C3 | 切片阅读角色与覆盖提示 | 全共享单元私有为空仍能正确展示 inherited；实际映射/对象漂移仍被原检查拒绝；不扫描历史对象 |
| C4 | 源规则、CLI、Harness 同步 | 续作不再要求整份读取 audit；真实报告/交接与权限回归；十个分发按 manifest 字节一致 |

先集中实现，运行短边界测试，再做相关 CLI/会话/切片集成与类型检查，一次分发核对后停止。不启动商城业务测试、真实模型、H5 或新试点。效率记录使用同一夹具的输出字节和读取范围，不推算整个交付提速百分比。

## 迁移与不在本轮执行的事项

不自动迁移商城状态、不删除历史对象、不清理审计、不修改商城 command.json 或本地引擎。历史 objects 可能仍被证据引用；本轮仅从默认阅读中排除。源工具接入后新增审计采用增量，旧证据原样验证。事实存储迁移继续采用既有显式入口。

新阅读视图按需生成，不新增强制 summary 文档。已完成的设计文档收敛与事实存储能力继续复用；不为了减少文件数量将不同业务真源拼成必须整读的大文件。

## 实施记录与退出结论

C1–C4 已完成仓库实施与工程验证。新模块 `aidlc-context-view.ts` 接入公共 CLI 和 Codex 的现有只读派发；保持原 grant、预算与写入操作限制。十个 Harness 的入口说明、OpenCode bootstrap、continuity/handoff Skill 和运行时交接提示同步使用新入口。

切片优化只新增动态 reading 视图中的 private/inherited 角色、覆盖计数、每文件体积与按需读取说明；不更改 generator v1 的对象、manifest 或原完整性算法。因此本次改进不要求为展示索引重新生成全部存量切片。共享字段无缺失时，空 private 视图正常；真实对象漂移和需求映射不一致仍拒绝。

验证结果见 `evals/context-simplification-2026-11-11/acceptance.json`。七个相关验证组覆盖分页拼接（含中文/emoji）、公开 JSON 摘要、真实 junction 拒绝、损坏兄弟状态隔离、单/分布局与默认单元、实际领取追加审计、共享切片、公共 CLI 无绑定只读、事实存储、交接报告及 37 个宿主路由场景；类型检查通过。十个分发 3,152 个映射文件逐字节一致，无额外 Core 文件。修复一个初始导入错误和协议行尾空白后收口；未据此反复执行业务测试。

退出条件已满足：本轮停止在源仓库及分发收口，不安装到商城、不迁移其事实存储、不删除其旧审计或对象、不重签证据。商城真正使用新默认入口与新增增量审计，仍需后续部署匹配版本；既有 G9 真实宿主资格边界不由本轮关闭。

后续按用户“根据最新的调整的版本重跑试点项目，看看效果”执行一次真实订单试点。新版 scripted 整链通过，真实订单在代码审查的准入重入路径停止；发布页仅完成准备。紧凑入口输出缩减 90.5%，但真实模型未调用该入口，最后一次请求仍有约 17.8 万输入 token（多数缓存），故不得将本轮工程退出解释为端到端效率优化完成。完整实测、失败证据边界与后续收口范围见 [新版试点复跑记录](evals/autonomy/p1-10/context-rerun-2026-11-11/review.md)。
