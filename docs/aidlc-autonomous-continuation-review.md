# 自主实施跨层契约与验收重评

本轮依据 IT-08 订单 r11 的真实失败，修正继续判定和验收方法；保持 HOLD，不创建业务工作流、不签 H5、不恢复旧 attempt、不新增 P2。历史 735 文件来源、IT-07 工程结果与 IT-08 失败原文保持，以新的路径证据解释当前结论。

## 1. 需要统一的条件

“能力尚未过期”与“能覆盖当前动作”是两个条件。Core 先验证当前授权、精确会话、真实配置、签名及原始输入，再使用共享时间判定。所需窗口沿用现有 action policy 和原 grant 剩余 clamp，不新增时长、不提高预算。

| 判定 | Core 职责 | 宿主职责 |
| --- | --- | --- |
| continue | 当前受管能力/接收结果原剩余窗口充分，提供当前事实与签名凭据 | 实时授权和路径校验，正式阶段进入后派发 |
| reprobe | 已知能力过期/覆盖不足时，在当前合法 grant 下选择一次真实新探测；轻量配置检查后重新计算 | 执行原会话、原预算内的受控探测/续验，恢复原精确阶段并核对正式 directive |
| stop | 非法授权/领取/来源/配置、未知事实、预算不足，或新观察/预检/发布后仍不足 | 停止派发并由原 Supervisor 对账，保留 unknown 和原领取，不自动恢复 |

原能力凭据不改日期。新增探测产生新 nonce/观测及原截止约束下的新凭据；这不授予新执行权限。一次 Core 准入最多一次新 observe；宿主最终派发边界最多一次续验与实时权限复核。预检耗时和发布锁耗时单独测试，发布锁内没有外部探测副作用。

## 2. 必须独立取证的路径

| 组 | 独立场景 |
| --- | --- |
| 共享时间判定 | 精确阈值、阈值前后、过期、缺当前凭据、预算不足、非法时间、pending/unknown、禁止续验、续验上限、发布阶段 |
| 真实 Core | 3600s grant 的能力老化、仍充分时不完整探针、轻检跨阈值、轻检跨能力到期、600s clamp、配置变更/unknown、预检消耗窗口、发布锁消耗窗口、新探针耗时、原 grant 到期/撤销、原始证据篡改 |
| 宿主调度 | 恢复原阶段、刷新后不足、恢复阶段耗时、新审批、在途/未知、权限准备后续验、二次检查仍不足、原等价失败计数保持 |
| 聚焦集成 | 真实 Core 投影与续验→原宿主控制器→真实 Gateway→实际 Node 命令，使用老化能力与长 grant，保留原能力日期和原 deadline |

测试的原生 adapter/授权属于显式工程夹具；聚焦集成实际执行 Core、签名与命令，但不代表真实模型、Native 全链、UI 还原或业务交付完成。

## 3. 对旧关闭结论的处理

IT-07 的历史正向工程链仍成立；它使用 600 秒 grant，不能证明 3600 秒 grant 下时间老化路径。IT-08 真实失败保持未通过。本轮即使局部路径全过，也只关闭所列路径，当前来源的完整发布整链、成功交付效率和 L3 均不自动关闭。

原验收脚本把多个故障族统一设为 covered-engineering 的做法停止沿用。新的机器清单逐行核对当前来源下实际输出的场景 ID 与断言结果，缺证、来源漂移或边界外的声明标记待验证；文件整体通过只证明其实际执行的场景。旧签名不会被改成新 checker 的当前业务凭据。

生产算法未变的历史证据可以保留其当时范围；阶段组合、生命周期、返修、UI、候选与完整 Native 在新来源下未整体验证的部分明确列为 release-revalidation-required。任何 Go 仍需新的完整审查与真实人类授权，本轮不生成 Go。

## 4. 验证与停止方式

先用无等待的时间真值表和 fake clock 验证，再运行真实 Core/宿主/聚焦命令及受影响短回归。失败按精确根因修正并保留原文，不扩大 timeout、不循环运行旧 Native 前缀。必要类型检查和分发一致性在最终来源完成；不重复未变性能采样。最终记录包含原记录摘要、来源差异、逐路径证据和仍开放的发布/业务项。
