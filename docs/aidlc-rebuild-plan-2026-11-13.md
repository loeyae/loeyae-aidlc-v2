# AIDLC 当前执行规则重建

本次目标：AIDLC 只提供一套围绕用户目标、实际实现与验收的执行规则。宿主负责执行和权限，不再发布旧阶段调度器及其兼容入口。Loeyae Boot 的领域包版本、内容和迁移不属于本次交付。

## 执行方案

1. **剥离领域变更**：核对上一轮改动的文件哈希，将 Loeyae Boot 改动保存为独立补丁后恢复其源仓库；框架验证使用通用案例。
2. **统一执行契约**：以目标、约束、已有授权、实际依赖和验收为依据持续实施。CR、续作和普通需求使用同一规则。只在重大未决决定、真实权限不足、写入冲突和必要外部条件处停止相关工作。
3. **重建披露结构**：一个短入口指向任务方法目录；只加载所选方法和相关事实，不加载完整阶段图、历史证据或全部 Provider 正文。质量和权限的基本规则常驻，领域知识按需读取。
4. **清理旧执行体系**：移除 orchestrate/module/autonomy、阶段 report/claim/grant、专用 wrapper、自动门禁 hook 及受管规则的源代码和分发入口。安装升级仅清理 AIDLC 拥有的旧文件；保留用户业务产物、真实批准、未知进程和非 AIDLC 配置。历史材料可读，但不能恢复成第二套执行模式。
5. **统一完成结论**：实施、验证、外部验收、提交/合并/部署及 CR 关闭分别依据实际事实判断。空任务列表、阶段耗尽、知识阅读、测试子集通过不能推出项目完成。失败、未验证、过期结果和已知缺陷必须保留；本地完成不能代替真实环境验收。结论是派生视图，不增加持久状态权威或执行许可证。
6. **保留独立能力与约束**：保留可独立使用的文档工具、安装所有权保护及 Provider 来源/完整性/权限边界。去除它们对旧流程身份的依赖；不能用知识加载替代质量验收，不能用测试通过授予发布权限。
7. **重建分发与验证**：十个宿主共享同一入口内容和规则源，重新生成产物；增加目标/CR/续作/外部等待/验证失效/权限案例、旧入口拒绝和安装保护测试。重大不兼容变更使用新主版本，未发布前不替换用户机器上的安装。

## 验收依据

- 发布内容只存在当前执行规则；CLI 不再路由到旧状态机或生成新的旧流程状态。
- 方法检索只返回目录元信息；读取一个方法不会加载其他方法及其前置阶段。基础质量与权限约束不会被按需选择过滤。
- 完成判定使用一份可复用实现；只读上下文没有完成权限，报告不运行命令、不修改记录、不签发授权。
- 沿用已有具体授权；重大新增决定及提交、推送、部署、破坏性操作仍按用户和宿主权限处理。
- 重验按相关输入变化触发；普通交付记录不强制重验，业务定义和代码变化仍会使相关验证失效。
- 安装升级不改项目 Git 配置，不删除用户记录，不覆盖未知安装或接管进程。
- Loeyae Boot 源仓库无本次改动，其改动仅保存在任务产物目录的独立备份中。

## 执行记录

### 已实施

- 当前版本为 **5.0.0**，这是删除旧执行接口的主版本变更。本记录说明实现与验证范围，提交状态以 Git 为准。
- `core/ENTRY.md` 是十个宿主入口的唯一来源；21 个方法保留在 `core/skills`，目录由技能元信息生成。方法查询先返回元信息，再显式读取所选正文，不展开阶段依赖。
- 移除 38 个阶段、38 个 sensor、旧调度器/会话许可/wrapper 及配套受管协议的活动源码和分发。CLI 的旧命令报错并提示当前用法，不隐式回到旧模式；OpenCode 只清理自己原先注入的旧指令。
- 共享执行、验证、授权、工程检查和 CR 规则已重建。项目 CI、真实验收、权限、并发写入边界继续有效；历史记录保留作事实参考，不再成为阶段重跑或补凭据的依据。
- 完成结论由 `aidlc-completion.ts` 统一推导；缺失、失败、过期、范围覆盖不足和未决项不能推出全部完成。必需交付动作未完成时，CR 关闭也不能完成。`work` 固定未评估，`assess` 不写状态、不运行检查、不认证输入事实、不授予权限。
- Provider 知识采用当前章节声明，读取保留来源锁、内容哈希、能力绑定和必需章节校验；移除阶段计划、签名阅读回执与旧门禁模型。DOCX/export 的实际产物验证、来源信任和文件保护保留。
- 安装不再配置项目控制平面 Git 策略；共享 Kiro 安装内容保持一致。一次性旧安装识别/备份仅用于保护所有权，不提供旧流程执行能力。
- Loeyae Boot 的 8 个改动文件经哈希核对后已单独备份并恢复，领域仓库工作区干净；框架中的 Boot 迁移文档及相关领域测试恢复原内容。本次未修改该包版本。
