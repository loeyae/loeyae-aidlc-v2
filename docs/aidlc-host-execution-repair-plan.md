# 宿主执行与流程减负修复（2026-11-12）

## 目标与边界

纠正 P1/P2 实施中把质量保证扩大为执行前置控制的偏差。默认由宿主根据用户授权连续实施，AI-DLC 提供任务方法和结果验收依据。流程状态落后不应中断开发；质量不达标必须继续修复，不能宣称完成。

本方案替代此前“继续修补默认门禁链再试跑”的收口方向。旧 P1/P2 控制面只保留兼容，不再作为普通实施入口，也不改写历史失败证据或自动迁移活动运行。

## 实施计划

1. 默认入口：CLI 增加无状态只读 work 上下文；所有 Harness 主 Skill 使用宿主直接执行，不再默认 next/bind/H5/report。无需调用 CLI 也可工作。
2. 规则与上下文：统一默认宿主协议；续作和交接以实际产物为依据。OpenCode 不再注入完整强制阶段链或在 idle 时调用控制器。文档按需加载，不生成新的执行计划/收据/状态权威。
3. 兼容隔离：原受管 API、历史 state/audit、签名证据不改；既有项目可依据实际代码在独立安全范围工作，不把过期 claim 变成全仓停机，也不暗中接管旧进程。迁移用户安装包属于部署，本轮构建各 Harness 分发，不擅自覆盖全局安装。
4. 验证：真实临时 Git 仓库内，用默认 CLI + 宿主命令完成实现、失败返修、验证、晚生成文档和续作；加入坏状态/过期记录、不存在 Git、缺失输入与越界路径等边界。类型检查、构建与分发一致性只执行必要一次。不创建新真实模型试点、不要求 H5。

## 需要退役的默认要求

专用 Supervisor/worker、模型/宿主白名单、逐工具准入、能力有效期刷新、语义步骤计数、grant/H5、逐阶段领取/report、签名候选汇合：全部退出默认使用路径。它们仍存在于显式调用的旧实验/兼容引擎，不通过放宽旧凭据校验实现迁移。

阶段文档生成、冗余摘要和状态同步：不再是开发前置条件。只保存业务所需产物，已有测试结果不因纯交付记录变化而失效。

## 数据约定

work 输出是一次性只读视图：目标、选定路径、Git HEAD/status/diff 统计、最多 8 个文档的有限片段及警告；不存盘、不签名、不承诺状态新鲜度、不授予权限。业务/验证初始化为 not_evaluated，性能为 not_measured；实际结果由宿主执行工具获得。旧状态只检测存在，不解析其 claim/期限，不用于判断是否可开始编码。

任务范围和验收使用现有设计及用户指令，不建立新强制 JSON 清单。完成时在单份报告/对话列出功能、验证、遗留决定和性能，性能未达目标不混写成业务失败。

## 停止条件

真实权限、重大待决事项、外部不可用、相关并发冲突和用户暂停才阻止相关动作。流程文档缺失、旧状态不一致、历史证据需要更新不停止独立实施。测试失败继续修复；无法通过时如实交付未完成项。

## 验证记录

上述四项已实施。默认入口、九个主 Skill 和 OpenCode 插件、六个相关能力 Skill、交接/续作及兼容协议边界已同步。未绑定旧会话的 Stop 直接返回，不加载 TS/Core；OpenCode 已删除 idle 调用和重入派发。

验证通过：真实临时 Git 中的宿主命令 RED→修复→GREEN→晚生成交付文档→续作；坏状态/无效绑定不阻断、无隐式状态/凭据写入、有限文档读取、无 Git 与缺失输入诊断、路径边界、Stop 不阻断。十种分发默认入口与协议路径、OpenCode 注入幂等及无 idle 事件、3183 文件一致性、TypeScript 检查通过。原始本地输出保存在 `.artifacts/host-execution-repair/validation.json`。

测试首轮因临时目录不能解析相对 tsx loader 失败，改为调用真实包入口 bin/cli.js 后通过；这是测试启动问题，不是业务试跑。未运行完整历史安装器/受管长链回归；本轮没有修改旧受管状态机、grant 或签名验证逻辑。根 state/audit 的 SHA-256 与本轮前记录一致。

限制：这证明默认执行路径不再受旧控制面拦截，不证明真实模型的业务/UI 交付或性能目标已经通过；旧 r17 结论不变。没有创建真实试点、没有 H5、没有改动全局已安装 Skill。仓库源码及十种分发已更新，外部已安装版本须正常升级后才使用新默认入口。旧受管引擎仍保留，不宣称已经物理删除全部 P1/P2 实现。
