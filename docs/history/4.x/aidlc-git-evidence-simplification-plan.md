# Git 与证据驱动的流程简化实施计划

2026-11-11；依据流程必要性审计及用户确认的简化方向。

目标：以设计/代码内容和真实证据判断工作，进度视图不成为读取、比较和恢复诊断的前置锁。保留批准事实、质量门禁、执行权限、并发写保护及未知副作用记录。Git 提交不是批准或测试通过的证明。

| 编号 | 实施内容 | 验收 |
| --- | --- | --- |
| G1 | 提供独立于 workflow/claim 的 Git 内容核对入口，包含未提交和未跟踪内容；不自动提交或改变阶段 | 缺失/损坏/过期流程状态不影响核对；拒绝越界路径；无写入 |
| G2 | 无变化状态保存不增加 revision/audit；无关领取更新允许锁内合并；绑定诊断与续领代次语义修正 | 真正同目标竞争仍拒绝；旧所有者不能写；转交不改变兄弟模块；批准门禁保持 |
| G3 | 局部证据复用只计算实际使用的局部摘要，复用现有失效机制 | 摘要与完整算法一致；不读取无关大文件；相关变更可见；最终候选仍全范围 |
| G4 | 减少宿主重复控制读取，按精确 workflow 查询绑定，普通只读动作不请求业务写入许可 | 原期限和预算有效；路径隔离有效；副作用前授权及最终门禁保持 |
| G5 | 同步 Core 协议、CLI 说明、分发与实施证据 | 类型检查、短边界、必要受影响集成检查、分发一致性通过 |

实施顺序 G1→G2→G3→G4→G5；每个改动组完成后集中运行短测试，最终一次汇合。不得重跑历史审计探针覆盖原始失败证据。不启动模型、真实 H5 或业务试点。

迁移边界：先解除内容核对对可变流程状态的依赖，并修正当前执行路径的高频成本。现有受管工作流的批准/完成事实不能从 Git diff 凭空重建；彻底删除旧路由状态，需要迁出其内嵌批准与报告事实后才能实施。尚未实现的迁移必须在实施记录中明确列出，不能把新增只读命令称为全面完成状态替代。

文档原则：只维护一份设计/验收事实来源，摘要和进度按需投影；不新增逐动作报告。宿主原则：Core 规定可执行条件与最终验证，宿主选择模型、工具与调度；只有实际具备可信拦截能力的适配器才能替换受限 gateway，不凭宿主名称推断能力。

## 完整优化分层与后续依赖

G1–G5 是可兼容落地的第一阶段，并非全部架构迁移。后续依次处理：

| 编号 | 需要继续完成的优化 | 依赖与验收 |
| --- | --- | --- |
| G6 | 将批准、完成报告及其来源绑定从可变进度中分离；进度可由 Git 管理的事实和有效证据重建 | 先定义旧记录无损迁移；删除进度视图后可重建但不能伪造批准；依赖/阶段切换由输入与证据决定；不得另增一套并行权威状态 |
| G7 | 合并多文档重复事实，设计/验收为唯一来源，其他材料按需派生 | 接在 G6 事实来源之后；同步 graph produces/consumes 与检查器，不仅修改文字规则；简单任务实际减少独立维护文件数 |
| G8 | 拆分普通语义检查器实际依赖，合并 P2 可合并持久事件，完善 busy/遗留锁诊断 | 不能直接把仍被执行器导入的文件排除摘要；持久 intent/预算/fencing 必须保留；短故障测试证明重启不重复副作用 |
| G9 | 提供经过能力验证的宿主原生工具/审批适配，收缩额外调度 | 可信前置拦截与用户授权来源必须存在；保留受限 gateway 作为兼容方案；不能凭产品名断言已支持 |

后续实施沿用同一计划，不为每个小修复重新创建试点。本表列出第二阶段范围；当前完成状态见下文“第二阶段实施记录”。不能据此宣布所有项目默认强制状态已全面替换为 Git。

## 第一阶段实施记录

G1–G5 已实现并通过本轮检查：

- `orchestrate state changes` 使用明确 Git 基线与可选路径，包含未提交、非忽略未跟踪、删除与合并冲突；无 workflow/session 依赖，不生成完成或批准结论。
- 使用进程内读快照，仅对无关 claim/selection 更新执行锁内条件合并；业务进度/范围/批准或同目标变化继续拒绝。无变化保存不写 revision/audit。JSON null/无效 binding 返回可操作诊断。
- 未过期普通续领保持 generation；过期恢复、所有权转交和 P2 新 attempt 仍轮换 generation。原 grant 期限不变。
- `readScopedSourceRevision` 供局部比较使用，接入语义复用、门禁和相关失效核对。生成新证据及最终候选仍使用完整摘要；没有把 null 全局摘要冒充有效生产证据。
- 精确 ownership 查询验证 global/registry/目标 lineage，不加载无关模块 state。依赖和最终汇合仍使用各自完整范围检查。
- 公开 read/rule 不触发 Core 许可往返；宿主路径限制、取消、期限、预算保持。prepare 内同一冻结输入验证共享一次，执行前/提交前动态权限检查不缓存。
- Core 协议、CLI 帮助、README 与各 Harness 入口说明已同步。十个分发已构建；未安装或替换机器全局 Skill。

### 关闭的生产路径缺口

- 已迁移工作流删除/误改 Markdown 视图，不再丢失历史批准或卡住正常读取。普通进度保存不改事实文件、不重写 Git 状态视图、不重复追加 STATE_UPDATED；兄弟模块与 registry 保持不变。领取/授权仍由原受控路径检查。
- 报告和重新验收记录绑定当时提交、产物/证据文件字节及无法解析的来源清单；历史通过不等于当前候选通过。事实先发布、运行文件后发布的中断不会回滚报告，revision 取单调上界，旧领取保守保留。迁移读写已加 fsync 和原子替换。
- 单文档格式必须显式标记并包含四个完整章节。标记采用后，不读取被替代的四份旧片段来补齐缺失或覆盖正文；测试用例、单元清单及独立前端材料不被排除。功能设计的 UC-D 单元归属、接口、数据源、错误处理和未决项检查均保留。
- 功能设计实际执行文件不导入 orchestrate/worker；身份仅绑定七个 TS 文件、固定 tsconfig、身份检查器、Node/平台及 tsx 传递运行依赖。加入未声明加载路径会拒绝生产证据；不会把真实依赖粗暴排除。
- P2 同一语义快照的重复 persist 不写盘；存储失败不记为成功，下一次可重试。计数/重复动作/新进展仍持久化。Core 无变化更新仍先检查当前授权和 fencing。
- producer/control 锁识别活跃 owner、确证已退出 owner 和未知 owner。活跃者有界等待；未知、异机、空旧锁和未完成 reaper 保留，不以 age 判定死亡。旧测试的活跃锁预期从 OWNER_UNKNOWN 调整为 LOCK_BUSY。
- 原生工具通道使用替换语义、冻结命令 id 和原 Gateway 保护，未知原生 shell/patch/MCP 不自动放行；要求签名能力记录、配置/HostRef 和当前授权。原生审批 API 仅供可信安装代码，核对用户事件、随机挑战、精确摘要、actor、截止与一次性 token，不暴露模型 JSON/CLI 签发入口。

### 验证与效率

独立索引：`docs/evals/git-evidence-migration-2026-11-11/acceptance.json`；各组保留 argv、耗时、stdout/stderr，不覆盖第一阶段或历史试跑证据。

短验证包括事实迁移与半写发布、设计缺节/未决项/UC-D 归属、真实独立 checker CLI、真实 OS 锁竞争、重复快照、原生通道实际本地文件读取、签名能力/撤销和原生审批协议。必要集成包括 P2 recovery、故障对账、Mermaid 和未声明依赖拒绝；另做类型检查、十个分发构建与逐字节核对。

实测采样：功能设计 checker 身份计算读取 **2,030 → 70** 个文件、**34,948,639 → 12,479,296** 字节，约 **303 → 46 ms**。保留 tsx/esbuild 实际依赖体积，未宣称只有七个文件的全部 IO。相同快照额外 persist 100 次为 **0 次持久写入**。两类设计各 **5 → 1** 份维护文档。上述不是完整业务交付提速比例。

### 剩余收口与停止条件

G6–G8 的本轮范围已通过局部与必要集成验证；不因这些改动重开业务试点。全量迁移、跨机器丢失本地运行信息的恢复不在本轮自动执行范围，不能以 Git checkout 重建活跃授权。

G9 的退出条件仍是：所选真实宿主提供可安装且不可被原生工具绕过的替换接口、可认证用户事件通道、与 HostRef/配置/原期限绑定的能力原始证据，并通过单次实际适配验证。当前只完成通用接入与工程边界，**不标记 G9 全部完成，也不自动放宽默认限制**。用户此前要求暂不真实试跑，因此本轮停在这项外部资格边界；没有用更多业务试点碰运气。

本轮收口：15 个验证组通过；十个分发 3,142 个映射文件字节一致，已扣除 manifest 明确声明的 Harness 覆盖文件后无额外 Core 文件。674 项历史输入和根 state/audit 保持不变。Windows 目录删除 EPERM 使用保留目录的原位生成规避，并完成清单/字节复核；未改构建器源码。两个新夹具入口/预期错误及分发清单分类修正的失败输出均保留，没有转记为生产缺陷。
