# Current test coverage

`npm test` builds all hosts and runs `scripts/core-test-suites.json`. It covers completion boundaries, read-only host context, explicit method selection, source pinning and knowledge integrity, module facts, hostile DOCX/export candidates, host detection, owned installation and ten-host distribution consistency. Knowledge discovery exposes unknown/conflicting applicability while required content stays blocked; an unidentified module cannot silently skip conditional requirements. The project case runs local consumers and HTTP checks, then an independent product oracle against the original requirements: green implementation tests can still miss a goal. It distinguishes semantic Markdown changes from delivery-note updates, preserves failed outputs and reuses unaffected results. Required CI, external acceptance and delivery remain separate completion conditions.

Retired engine tests, their dedicated fixtures, old runners and one-time evaluations are removed from the current tree. They remain accessible at Git commit `cd703ab996b32b18b4ca533420226d21229830bf` and earlier (`git show <commit>:<path>`). The retained Provider lifecycle test exercises actual Git objects, pinned revisions, trust/configuration checks and hostile install hooks without the removed stage/session fixture. No old engine is loaded to run the current suite.

| Command | Additional coverage |
| --- | --- |
| `npm run test:install` | 18 installer lifecycle cases: ownership, user changes, upgrades, rollback, unknown files, host configuration and shared assets |
| `npm run test:package -- --previous-ref <commit>` | Clean source archive and actual release tarball; production dependencies, ignored install scripts, automatic build, ten-host parity, real HTTP global install, upgrade and rollback |
| `npm run test:providers -- --providers <registry.json>` | Explicit immutable `document-render` checkout: actual export and DOCX candidate checks; registry format is `aidlc.integration-providers/v1` with `source`, `revision` and `checkout` per Provider |

The Python DOCX/export cases in `npm test` run missing-provider diagnostics by default. Actual rendering needs the explicitly configured document Provider; a diagnostic pass does not claim production rendering or final page-layout acceptance. External rendering tests remain in the tree and are not silently reported as passing when the package is absent.

Test logs default to independent temporary directories; use `.artifacts/` for locally retained results. Do not commit run outputs or copy this coverage table into workflow evidence files. Only add regression cases for current behavior, a verified defect or a real quality/permission boundary.

Quality and permission invariants are carried forward through current behavior tests: incomplete/failed/stale acceptance never becomes complete, projections grant no permission, missing approval is not synthesized, retired commands never execute, package sources and actual document candidates remain validated, and installation cannot overwrite unowned/user-modified files. The host still identifies goals, determines relevant input changes and supplies facts; these fixtures do not prove that a model discovers omissions or that approvals transfer between hosts. Ten-host distribution parity does not establish cold-start, cross-session/multi-person collaboration, automatic process recovery or safe handling of a lost external-operation response. Those need actual host scenarios with unchanged acceptance standards; measure successful goal delivery, defects, human interventions, repeated work and elapsed time from existing logs, not document/test counts. Do not add project gates or require recurring full pilots to produce these measurements.
