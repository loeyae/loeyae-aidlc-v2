# Current test coverage

`npm test` builds all hosts and runs every suite in `scripts/core-test-suites.json`. It covers short-run selection and failure reporting, compact read-only queries (navigation, JSON projection, complete reference candidates, structured case boundaries and path confinement), completion boundaries, read-only host context, explicit method selection, source pinning and knowledge integrity, module facts, hostile DOCX/export candidates, host detection, owned installation and ten-host distribution consistency. Knowledge discovery exposes unknown/conflicting applicability while required content stays blocked; an unidentified module cannot silently skip conditional requirements. The project case runs local consumers and HTTP checks, then an independent product oracle against the original requirements: green implementation tests can still miss a goal. It distinguishes semantic Markdown changes from delivery-note updates, preserves failed outputs and reuses unaffected results. Required CI, external acceptance and delivery remain separate completion conditions.

Use the same runner for a short regression, then widen verification according to the actual change:

```text
npm test -- --list
npm test -- --suite test_verification_runner --suite test_scoped_query --fail-fast
```

Suite names are exact and repeatable. Unknown or empty selections fail before execution. A selected run still builds the distribution and prepares the existing test environment; its output and existing `results.json` identify the limited selection. `--fail-fast` retains the actual failure and marks later selected tasks as not run. The default full suite continues independent tests after a test failure; a failed build prevents dependent tests in either mode. A selected pass never replaces required full-suite/CI acceptance. Full raw outputs remain in the original per-test logs, and reusing an occupied result directory is rejected before tasks run so earlier evidence is not overwritten. Use a new output directory for a necessary new execution, or reference the old result without executing it again.

Retired engine tests, their dedicated fixtures, old runners and one-time evaluations are removed from the current tree. They remain accessible at Git commit `cd703ab996b32b18b4ca533420226d21229830bf` and earlier (`git show <commit>:<path>`). The retained Provider lifecycle test exercises actual Git objects, pinned revisions, trust/configuration checks and hostile install hooks without the removed stage/session fixture. No old engine is loaded to run the current suite.
